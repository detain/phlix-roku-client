# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** Verify a slice with the bsc gate `npx -y brighterscript@0.72.5 --project bsconfig.json`; on success it prints only "Parsing/Validating finished" timing lines (no error lines), so confirm with `echo "bsc exit: $?"` (exit 0) rather than scanning stdout. bsc + an independent reviewer are the ONLY quality bar — CI is informational and the device is unavailable.
- **[convention]** `GET /api/v1/admin/*` is gated by `AdminMiddleware` (requires `users.is_admin=1` AND `status='active'`; non-admin→403, no-token→401). Per-library mutation routes are BARE `/libraries/{id}/{scan,rescan,...}` gated INTERNALLY by `requireAdmin` (NOT under `/admin`). `GET /api/v1/auth/me` is AUTH-gated (NOT admin) and carries `is_admin`/`status` — use it to gate admin UI client-side. `sendRaw` prepends `/api/v1`, so a method path of `/admin/users` hits `/api/v1/admin/users`. A user/library/collection id is a UUID → path directly (no `UrlEncode`).
- **[convention]** When documenting a new scene, update README.md's "Project Structure" scene inventory + the API Endpoints table + (if it adds Home header nav) the navigation section — NOT DEVELOPER.md (lib/manager-focused). There is NO CHANGELOG.md — do not create one.
- **[convention]** When staging a feature commit, `git add` the specific source dirs/files (`git add source/ components/ <specific files>`) — do NOT `git add .` — so untracked tooling dirs like `.claude/skills/` stay out; verify with `git diff --cached --name-only | grep -q '.claude'`.
- **[fix]** `gh pr merge <n> --squash --delete-branch` can fail with `GraphQL: Head branch is out of date` even right after a successful push. Retry the SAME command after `sleep 5` — it succeeds once GitHub recomputes mergeability. Confirm with `gh pr view <n> --json state,mergeCommit`.
- **[pattern]** A conditional/hidden header button (`visible="false"`, revealed only when a flag like `m.isAdmin` is set after a `getMe` read): a `SetFocus(true)` on a hidden node is a runtime defect bsc won't catch. Guard the directional nav INTO that button's column with the SAME flag that reveals it.
- **[convention]** Collection read routes (`/collections`, `/collections/{id}`) and `/admin/dashboard/*` are device-only-verifiable. `/collections/{id}` EMBEDS its items as `{collection, items, total}` — there is NO `/collections/{id}/items` route.
- **[pattern]** When pairing subagent review with coordinator edits: instruct the review subagent "Do NOT modify any code — review only" and have it APPEND findings to the worklog; the coordinator then applies fixes and re-runs the bsc gate.
- **[gotcha]** Do NOT both hand-implement/hand-edit a slice in the coordinator AND delegate the SAME slice to subagent(s) — they race / produce no-op duplicate work. This recurs EVERY session: F11b hand-wrote 7 files + the worklog review section THEN spawned author + code-reviewer agents for the identical work; F11c hand-wrote all scene files + the worklog summary THEN spawned TWO author agents, AND hand-edited README.md + appended the worklog Scribe section THEN spawned TWO `scribe` agents for the same docs. Decide ONCE up front per slice: delegate impl/review/docs OR do it inline, never both — and never spawn duplicate agents (or two at once) for one job.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript runtime type-mismatch and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (year, `progress_percent`, `item_count`, `date_taken_year`, `is_admin`), branch on `type(x) = "String" or type(x) = "roString"` else coerce via `str(Int(x)).trim()`. Only `<> ""`-guard fields KNOWN to be strings (and guard `DoesExist` + `<> invalid` first). `Int()` on a String can also RAISE — type-guard the numeric family first. The same applies at the CALL site: passing a possibly-non-String field into a param typed `as String` blows up at runtime.
- **[convention]** `is_admin` arrives from JSON as a TINYINT (0/1, sometimes Boolean) — read it ONLY via `Utilities.IsAdminUser(user)` (it type-guards Boolean/Integer/Float, returns false on invalid/missing). NEVER compare it (or any possibly-numeric field) with `<> ""`.
- **[pattern]** When adding a browse/list or button-action scene that mirrors an existing one, copy the closest template verbatim (UserAdminScene ⟵ LibraryAdminScene; UserAdminActionsScene ⟵ LibraryAdminActionsScene). Back the current list with `m.users`/`m.rows` so the `itemSelected` index maps to the right object, gate the list field on `type(x) = "roArray"` (reset to `[]` first), and guard EVERY string field read with `DoesExist + <> invalid + <> ""`.

- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript Integer-vs-String type-mismatch and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (`year`, `progress_percent`, `item_count`, `is_admin`, `start_time`, `end_time`, `duration`, `priority`, `episode_number`, `max_recordings`, channel `number`): guard `DoesExist`+`<> invalid` ONLY, then coerce via `str(Int(x)).trim()` (or pass to a helper that numerically guards `<= 0`). `Int()` on a String can also RAISE — type-guard the numeric family first. - **[gotcha]** Server JSON field-name landmines that bsc can't catch: some list rows have NO top-level `id` — e.g. a live-TV series rule's identifier is `rule_id`, so never read `rule.id`. Read the verified server contract in the slice worklog for the exact key before reading any `.id`.
- **[gotcha]** `is_admin` arrives from JSON as a TINYINT (0/1, sometimes Boolean) — read it ONLY via `Utilities.IsAdminUser(user)` (type-guards Boolean/Integer/Float, false on invalid/missing). NEVER compare it (or any possibly-numeric field) with `<> ""`.
- **[gotcha]** A 401/403/400/404/500 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with no expected data key. Do NOT assume an auth/validation/error failure yields `resp.ok = false`. Always read the SPECIFIC expected key (`resp.data.DoesExist("programs"/"recordings"/"rules"/"users"/"channels")` + `type()="roArray"`) and degrade to a placeholder ("Live TV unavailable") on its absence.
- **[gotcha]** ApiClient getter return-shapes are INCONSISTENT — check the source before consuming. `getLibraries()` UNWRAPS to the bare ARRAY, whereas admin getters and `getCollections()`/`getFavorites()`/`getAlbums()`/`getGuide()`/`getRecordings()`/`getSeriesRules()`/`getChannels()` return the WHOLE envelope (`resp.data.<key>` guarded by `DoesExist` AND `type()="roArray"`). Copying a sibling scene's access for a getter with a different shape yields a silently EMPTY list. Verify by reading the function body.
- **[convention]** Wire each new read/action through THREE coupled edits, keeping op strings identical across all: a typed ApiClient method (`m.request("GET", "/admin/livetv/guide", invalid)`), an `else if req.op = "<op>"` branch in `components/ApiTask.brs` (`result.ok = (result.data <> invalid)`), and the scene's `m.apiTask.request = { op: "<op>" }`. Bodyless POST mutations go through `m.request("POST", path, invalid)` (sendRaw issues a real bodyless POST when body=invalid). `sendRaw` prepends `/api/v1`, so a method path of `/admin/livetv/guide` hits `/api/v1/admin/livetv/guide`.

- **[convention]** Cross-component callable subs MUST be declared in the target component's `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` (e.g. AdminScene→GuideScene) needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` across the boundary require it.
