# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** Components now live in top-level `components/` (git-mv'd out of `source/components/`); `bsconfig.json` globs `manifest + source/**/*.brs + components/**/*.{brs,xml} + images` and `make package` ships `manifest source components images`. Keep new scene files under `components/`, not `source/components/`.
- **[fix]** When `bsc` fails BS1140 "Cannot find function '<Helper>'" because a shared helper (e.g. `UrlEncode`) was defined inside a module-specific file like `HlsPlayer.brs` that the calling component doesn't include, MOVE the helper into `source/lib/Utilities.brs` (the commonly-included shared module) rather than adding the niche file to every component's script-include list. Delete the original definition to avoid a duplicate-declaration error.
- **[gotcha]** `roUrlTransfer`'s synchronous `GetToString`/`PostFromString` do NOT expose the HTTP status code, so you cannot detect a 401 (or any status) with them. To read `GetResponseCode()` you must go async: `SetPort(roMessagePort)` + `AsyncGetToString`/`AsyncPostFromString`, then `wait(...)` for an `roUrlEvent` and call `event.GetResponseCode()` / `event.GetString()`. Set `RetainBodyOnError(true)` so the error-response body is still parseable.
- **[gotcha]** `wait(0, port)` blocks FOREVER until a message arrives — `roUrlTransfer.SetTimeout(ms)` bounds the transfer, NOT the `wait()`. If the transfer ends without posting an event, `wait(0,...)` hangs the calling thread. Use a bounded `wait(<ms slightly above SetTimeout>, port)` and treat a zero/non-`roUrlEvent` return as a timeout (then `AsyncCancel()`).
- **[gotcha]** Subagents in this workspace are harness-blocked from running `npx`/`npm`/`bsc`/`gh`/`git` — delegate file edits to them but run the `bsc` gate, git, and PR commands from the coordinator (main) session yourself. State this constraint in the subagent prompt so it doesn't waste turns attempting blocked commands.
- **[gotcha]** BrightScript's default numeric type is a 32-bit Integer, so `Int(seconds * 10000000)` for 100ns playback ticks OVERFLOWS past ~214 seconds (silently wrong on long media). Track playback position/throttle in SECONDS (Float) internally and convert to ticks only at the API boundary via a helper that does Double math and returns `LongInteger` (e.g. `SecondsToTicks(seconds as Double) as LongInteger` → `seconds * 10000000.0`). Put such shared converters in `source/lib/Utilities.brs` since it's already script-included everywhere.
- **[pattern]** Bound any SceneGraph repeat-`Timer` poll loop (e.g. transcode-status polling) with an explicit counter (`m.pollCount`, reset to 0 when the timer starts, stop the timer + surface an error past a cap like >30 polls). A poll that only stops on ready/failed will spin forever if the job hangs — the terminal states are not guaranteed to arrive.
- **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — without it a `scene.LoadFoo(...)` call from another scene fails at runtime ("function not found") and `bsc` does NOT catch it (it only validates intra-scope symbols). When adding a new scene that a parent invokes via `CreateObject("roSGNode","FooScene")` + `scene.LoadFoo(...)`, declare every such entry-point in the new scene's `<interface>`.

A read-only server scout in this session claimed `runtime` was in seconds; that was WRONG. When a scout/Explore agent reports a field's units or contract detail, treat it as a hypothesis and prefer the convention already verified against server source by a prior slice over a fresh scout's claim.
- **[gotcha]** The `getLibraryItems` ApiClient call has two modes: passing `options.parentId` switches to direct-children mode (`parentId=<id>`, OMITS `topLevel`) for series→season→episode drill-down; otherwise it sends `libraryId=<id>&topLevel=1` (top-level browse). The `/media` endpoint returns children `ORDER BY name` only (no season/episode-number sort option), so any season/episode list MUST be re-sorted client-side (`SortByEpisodeOrder` in Utilities) — don't assume server ordering.

- **[gotcha]** When a `.brs` value may arrive as either a parsed assoc OR a raw JSON string (e.g. a continue-watching item's `metadata`), guard with `if type(meta) = "roAssociativeArray"` BEFORE calling `.DoesExist`/indexing it. Calling assoc methods on an `roString` crashes at runtime and `bsc` does NOT catch it — an `<> invalid` guard alone is insufficient.
- **[pattern]** Drive a multi-step API flow (getLibraries→getContinueWatching; or getItem→getItemPlaybackInfo→PlayerScene.Show) through ONE observed `ApiTask` node, firing each next op only from the prior op's `OnApiResponse` branch — never two `control="run"` outstanding on one task. Add a re-entrancy guard (e.g. early-return if `m.pendingResume <> invalid`) so a rapid double-select can't fire a second concurrent run; clear the flag when the launch completes.
- **[pattern]** Roku resume-from-position: seek on the FIRST `state="playing"` transition guarded by a one-shot `m.resumeApplied` flag (the single guard also covers the transcode-fallback PlayHls path, which yields its own "playing"). Don't seek before content loads. Make `resumeSeconds` an OPTIONAL arg (guard invalid/≤0 → 0) so existing callers like DetailScene that omit it still play from the start.
- **[gotcha]** The continue-watching endpoint is registered at TWO paths: `/api/v1/me/continue-watching` (daemon, `Application.php` — what the Roku `ApiClient.getContinueWatching()` calls) and `/api/v1/users/me/continue-watching` (`WebPortalRouter`). Its items are RAW `playback_state`+`media_items` JOIN rows (NOT run through MediaItemShaper) so there is NO `poster_url`; `position_ticks`/`duration_ticks` are 100ns ticks; the server already excludes ≥95%-complete items, so the client must not re-filter.
- **[gotcha]** Do NOT both delegate a fix to a subagent (via SendMessage) AND hand-apply the same edits in the coordinator session — they race on the same file. In this session the coordinator messaged the fixer agent the 3 review fixes, started a background poll for them, then also Edited the same file itself, producing a malformed `if`/`end if` block that needed a second corrective edit. - **[gotcha]** `ApiTask` ops set `result.ok = (result.data <> invalid)`, but `ApiClient.request()` returns `raw.json` for ALL status codes and the favorite/rating/mutation endpoints return a JSON body (`{message}` / `{error}`) on BOTH success and failure. So an HTTP-error-with-body (e.g. a 400 on an out-of-range rating) sets `ok=true` and any `not resp.ok` optimistic-revert branch NEVER fires — only a true network failure / empty body reverts. Mutations through ApiTask therefore cannot detect server rejection; the server is authoritative only on the next read (getItem). Don't rely on `resp.ok` to catch 4xx unless you change `request()`/`sendRaw` to surface the HTTP status.
- **[gotcha]** A custom focus state machine over sibling SceneGraph nodes (e.g. an `m.actionFocus` driving `SetFocus` across play/favorite/rating Buttons) must CONSUME (`handled=true`) every directional key while the strip is entered — including no-op directions — so the framework's default arrow navigation can't silently move focus to a sibling without updating your state variable, which would then fire the wrong button's `buttonSelected` on OK. (In practice plain `Button` siblings inside a `Rectangle` — not a LayoutGroup/RowList, no `next*` wiring — usually don't auto-navigate, but this is device-only-unverifiable, so own the input defensively.)
