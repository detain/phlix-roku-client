# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** When documenting a new scene, update README.md's "Project Structure" scene inventory + the API Endpoints table + (if it adds Home header nav) the navigation section — NOT DEVELOPER.md (it is lib/manager-focused and does NOT enumerate scenes). There is NO CHANGELOG.md — do not create one.
- **[convention]** When staging a feature commit, `git add` the specific source dirs/files (`git add source/ components/ <specific files>`) — do NOT `git add .` — so untracked tooling dirs like `.claude/skills/` stay out; verify with `git diff --cached --name-only | grep -q '.claude'`. (Note: `gh pr create` will still warn "1 uncommitted change" for that untracked `.claude/skills/` dir — harmless.)
- **[convention]** New scenes use `function OnKeyEvent(key as String, press as Boolean) as Boolean`; back → `Teardown()` + `m.top.Close()`. Pair EVERY `ObserveField` with `UnObserveField` in `Teardown` (list field's itemSelected/itemFocused + the apiTask `response` field). `LibraryScene.brs`'s older `sub OnKeyEvent ... as Boolean` form is the exception — don't copy it.
- **[pattern]** When adding a browse/list scene that mirrors an existing one, copy the closest template verbatim (read-only F9b scenes ⟵ LiveTvScene/UserAdminScene). Back the current list with `m.<rows>` so the `itemFocused`/`itemSelected` index maps to the right object, reset it to `[]` first, gate the list field on `resp.data.DoesExist("<key>") AND type(x) = "roArray"`, and guard EVERY string field read with `DoesExist + <> invalid + <> ""`. For a READ-ONLY list (selection inert), `OnRowSelected` is a bare `return` no-op and there is only ONE op per scene → no `m.pendingOp` needed; keep the Init→fire→OnApiResponse shape.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript Integer-vs-String type-mismatch and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (`year`, `progress_percent`, `item_count`, `is_admin`, `start_time`, `end_time`, `duration`, `priority`, `episode_number`, `max_recordings`, channel `number`): guard `DoesExist`+`<> invalid` ONLY, then coerce via `str(Int(x)).trim()` (or pass to a helper that numerically guards `<= 0`). `Int()` on a String can also RAISE — type-guard the numeric family first. Same applies at the CALL site: passing a possibly-non-String field into a param typed `as String` blows up at runtime.
- **[gotcha]** Server JSON field-name landmines that bsc can't catch: some list rows have NO top-level `id` — e.g. a live-TV series rule's identifier is `rule_id`, so never read `rule.id`. Read the verified server contract in the slice worklog for the exact key before reading any `.id`.
- **[gotcha]** `is_admin` arrives from JSON as a TINYINT (0/1, sometimes Boolean) — read it ONLY via `Utilities.IsAdminUser(user)` (type-guards Boolean/Integer/Float, false on invalid/missing). NEVER compare it (or any possibly-numeric field) with `<> ""`.
- **[gotcha]** A 401/403/400/404/500 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with no expected data key. Do NOT assume an auth/validation/error failure yields `resp.ok = false`. Always read the SPECIFIC expected key (`resp.data.DoesExist("programs"/"recordings"/"rules"/"users"/"channels")` + `type()="roArray"`) and degrade to a placeholder ("Live TV unavailable") on its absence.
- **[gotcha]** ApiClient getter return-shapes are INCONSISTENT — check the source before consuming. `getLibraries()` UNWRAPS to the bare ARRAY, whereas admin getters and `getCollections()`/`getFavorites()`/`getAlbums()`/`getGuide()`/`getRecordings()`/`getSeriesRules()`/`getChannels()` return the WHOLE envelope (`resp.data.<key>` guarded by `DoesExist` AND `type()="roArray"`). Copying a sibling scene's access for a getter with a different shape yields a silently EMPTY list. Verify by reading the function body.
- **[convention]** Wire each new read/action through THREE coupled edits, keeping op strings identical across all: a typed ApiClient method (`m.request("GET", "/admin/livetv/guide", invalid)`), an `else if req.op = "<op>"` branch in `components/ApiTask.brs` (`result.ok = (result.data <> invalid)`), and the scene's `m.apiTask.request = { op: "<op>" }`. Bodyless POST mutations go through `m.request("POST", path, invalid)` (sendRaw issues a real bodyless POST when body=invalid). `sendRaw` prepends `/api/v1`, so a method path of `/admin/livetv/guide` hits `/api/v1/admin/livetv/guide`.
- **[convention]** `GET /api/v1/admin/*` is gated by `AdminMiddleware` (requires `is_admin=1` AND `status='active'`; non-admin→403, no-token→401). `/admin/livetv/*` is registered inside a `try/catch` → the WHOLE route group 404s when Live TV is unconfigured. Per-library mutation routes are BARE `/libraries/{id}/{scan,...}` gated INTERNALLY by `requireAdmin` (NOT under `/admin`). `GET /api/v1/auth/me` is AUTH-gated (NOT admin) and carries `is_admin`/`status` — use it to gate admin UI client-side. UUID ids path directly (no `UrlEncode`).
- **[convention]** Cross-component callable subs MUST be declared in the target component's `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` (e.g. AdminScene→GuideScene) needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` across the boundary require it.
- **[pattern]** Verify a slice with the bsc gate `npx -y brighterscript@0.72.5 --project bsconfig.json`; on success it prints only "Parsing/Validating finished" timing lines (no error lines). Confirm with `echo "exit: ${PIPESTATUS[0]}"` (exit 0) rather than scanning stdout. bsc + an independent reviewer are the ONLY quality bar — CI is informational and the device is unavailable.
- **[env]** Per-slice specs, the VERIFIED server contract, and worklogs live OUTSIDE the repo at `/home/sites/phlix/steps/<SLICE>-roku-*.worklog.md`. Read/author the slice worklog FIRST: it carries the confirmed route table, auth status, and response shapes scouted from `phlix-server`. Don't guess the filename — `ls /home/sites/phlix/steps/ | grep -i <slice>` to get the exact name, then Read it.
