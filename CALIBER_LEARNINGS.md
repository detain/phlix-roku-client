# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Do NOT both delegate a slice to a subagent AND hand-implement the same slice in the coordinator — they race / produce no-op duplicate work. This recurs EVERY session: in F11b the coordinator hand-WROTE all 7 files (ApiClient/ApiTask/AdminScene edits + 4 new scene files) AND its CHANGE LOG, THEN spawned an author agent for the identical work; it ALSO hand-wrote the worklog `## CODE REVIEW` section THEN spawned a code-reviewer for the same review. Decide ONCE up front per slice: delegate the impl/review/docs OR do it inline, never both — and never spawn duplicate agents for one job.
- **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` from another scene require it. Verify caller arg arity/order matches the callee signature.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript runtime type-mismatch and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (year, `progress_percent`, `item_count`, `date_taken_year`), branch on `type(x) = "String" or type(x) = "roString"` else coerce via `str(Int(x)).trim()`. Only `<> ""`-guard fields KNOWN to be strings (and even then guard `DoesExist` + `<> invalid` first). `Int()` on a String can also RAISE — type-guard the numeric family before `Int()`.
- **[gotcha]** A 401/403 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with no expected data key. Do NOT assume an auth failure yields `resp.ok = false`. Make empty/error renders safe by checking the EXPECTED key (`resp.data.DoesExist(...)`) and degrading to a placeholder (`[]` / "Never scanned"), not by trusting `ok`.
- **[pattern]** When adding a browse/list/menu screen that mirrors an existing one, copy the closest template's idiom verbatim (LabelList-of-names ⟵ CollectionsScene/MusicScene/AdminScene; button-action surface ⟵ HomeScene header buttons / MusicScene mode buttons). Back the CURRENT list with `m.rows`/`m.items`/`m.libraries` so the `itemSelected` index maps to the right object, gate the list field on `type(x) = "roArray"` (reset to `[]` first), pair EVERY `ObserveField` in `Teardown`, and `back` → `Teardown()` + `m.top.Close()`.
- **[pattern]** Combine subagent review with coordinator edits cleanly: instruct the review subagent "Do NOT modify any code — review only" and have it APPEND findings to the worklog; the coordinator then applies fixes and re-runs the bsc gate. On a device-only-unverifiable target, bsc + an independent reviewer are the only quality bar — CI is informational.
- **[convention]** Components live in top-level `components/` (git-mv'd out of `source/components/`); `bsconfig.json` globs `manifest + source/**/*.brs + components/**/*.{brs,xml} + images`. Put new scene files under `components/`, not `source/components/`. (CLAUDE.md still says `source/components/` — it is stale; `ls source/components/` fails.) Each new `.xml` MUST `<script>`-include the full transitive closure (Storage+Utilities+ApiClient+AppContext+own .brs) — a component scope does NOT auto-include `pkg:/source`.
- **[convention]** New scenes use `function OnKeyEvent(...) as Boolean` (Favorites/Music/Admin/Dashboard/LibraryAdmin convention); `LibraryScene.brs`'s older `sub OnKeyEvent ... as Boolean` form is the exception — don't copy it.
- **[convention]** `GET /api/v1/admin/*` is gated by `AdminMiddleware` (requires `users.is_admin=1` AND `status='active'`), but per-library mutation routes are BARE `/api/v1/libraries/{id}/{scan,rescan,match-metadata,scan-status}` gated INTERNALLY by `requireAdmin($request)` (NOT under `/admin`). `GET /api/v1/auth/me` is AUTH-gated (NOT admin) and carries `is_admin`/`status` — use it to gate admin UI client-side. A library/collection id is a UUID → path directly (no `UrlEncode`).
- **[env]** Per-slice specs, the VERIFIED server contract, and worklogs live OUTSIDE the repo at `/home/sites/phlix/steps/<SLICE>-roku-*.worklog.md`. - **[convention]** `is_admin` arrives from JSON as a TINYINT (0/1, sometimes Boolean) — read it ONLY via `Utilities.IsAdminUser(user)` (it type-guards Boolean/Integer/Float, returns false on invalid/missing). NEVER compare it (or any possibly-numeric field) with `<> ""`: an Integer-vs-String compare raises a runtime type-mismatch that CRASHES the render and `bsc` does NOT catch it.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript runtime type-mismatch and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (year, `progress_percent`, `item_count`, `date_taken_year`), branch on `type(x) = "String" or type(x) = "roString"` else coerce via `str(Int(x)).trim()`. The same applies at the CALL site: passing a possibly-non-String field into a param typed `as String` blows up at runtime.
- **[gotcha]** A 401/403/400/404 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with no expected data key. Do NOT assume an auth/validation failure yields `resp.ok = false`. Read the SPECIFIC expected key (`resp.data.DoesExist("users"/"user"/"message")`) and degrade to a placeholder; for action responses write a `MessageOf(resp)` helper that reads message-then-error-then-generic.
- **[gotcha]** ApiClient getter return-shapes are INCONSISTENT — check the source before consuming. `getLibraries()` UNWRAPS to the bare ARRAY, whereas admin getters and `getCollections()`/`getFavorites()`/`getAlbums()` return the WHOLE envelope (`getAdminUsers()` → `resp.data.users` guarded by `DoesExist("users")` AND `type(x)="roArray"`; `getAdminUser()` → `resp.data.user`). Copying a sibling scene's access for a getter with a different shape yields a silently EMPTY list. Verify by reading the function body.
- **[convention]** Bodyless POST mutations go through `m.request("POST", path, invalid)` — `sendRaw` does `SetRequest("POST")` then `AsyncGetToString()` when `body = invalid`, issuing a real bodyless POST (NOT a GET). POSTs carrying a body pass a literal AA (e.g. `setUserAdmin` sends `{ is_admin: isAdmin }` → `FormatJSON` → `true`/`false`). Wire each new admin action as a new `ApiTask` op (`result.ok = (result.data <> invalid)`) AND a typed ApiClient method.
- **[pattern]** For a scene with multiple action buttons that each fire ONE serialized request: use a SINGLE ApiTask and an `m.pendingOp` guard (invalid = idle; mirrors HomeScene's `m.pendingResume`). Every entry point bails when `m.pendingOp <> invalid`; in `OnApiResponse` clear `m.pendingOp = invalid` FIRST, THEN optionally chain a follow-up (e.g. a state refresh after a mutation) so it runs as a fresh serialized request — never two `control="run"` outstanding. A read whose result must stay visible (e.g. reset-password's one-time password) must NOT auto-chain a refresh.

- **[fix]** `gh pr merge <n> --squash --delete-branch` can fail with `GraphQL: Head branch is out of date` even right after a successful push. Retry the SAME command after `sleep 5` — it succeeds once GitHub recomputes mergeability. Confirm with `gh pr view <n> --json state,mergeCommit`.
