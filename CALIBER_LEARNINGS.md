# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** Hub-mode persistence keys: `connection_kind` ("hub"/"direct", absent→treated as direct), `active_server_id`, `active_server_name`. On logout, `Storage.delete` all three but KEEP `server_url` (the connect endpoint). Boot gate order in `PhlixApp.Init`: `IsServerConnected()` → `GetConnectionKind()="hub"` (validate via `GetHubApiClient` then `GetActiveServerId()<>""` ? Home : ServerPicker) → else direct `checkAuth()`.
- **[gotcha]** Guarding a possibly-numeric/bool JSON field with `<> ""` raises a BrightScript Integer-vs-String type-mismatch and CRASHES the render — bsc does NOT catch it. For any field the server contract does NOT type as String (`year`, `progress_percent`, `item_count`, `is_admin`, `is_active`, `rating`, `priority`, channel `number`, server `libraryCount`/`lastSeenAt`, health `version`): guard `DoesExist`+`<> invalid` ONLY, then coerce via `str(Int(x)).trim()` (`Int()` on a String can also RAISE — type-guard the numeric family first). A possibly-string field that IS safe to compare (health `status="ok"`, server `status="online"`) still needs `type(s)="String" or "roString"` before the `=`. A JSON value passed into a param typed `as String` (an id in a URL path) must be stringified BEFORE crossing.
- **[gotcha]** `is_admin`/`is_active`/`pin_required_for_admin` arrive from JSON as TINYINT (0/1, sometimes Boolean) — read truthy flags ONLY via `Utilities.IsAdminUser(user)` or the generic `IsTruthyFlag(container,key)`. NEVER compare with `<> ""`.
- **[gotcha]** A 401/403/400/404/500 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with no expected data key. Do NOT assume an auth/validation/error failure yields `resp.ok = false`. Always read the SPECIFIC expected key (`resp.data.DoesExist("profiles"/...)` + `type()="roArray"` for lists).
- **[gotcha]** Server JSON field casing differs by endpoint — `/me/servers` is CAMELCASE (`serverId`/`serverName`/`libraryCount`/`relayActive`/`status`) while most server endpoints are snake_case; some list rows have NO top-level `id` (a live-TV series rule's identifier is `rule_id`). Read the verified server contract in the slice worklog for the exact key/casing before reading any field.
- **[convention]** `GET /api/v1/admin/*` is gated by `AdminMiddleware` (requires `is_admin=1` AND `status='active'`; non-admin→403, no-token→401). `/admin/livetv/*` is registered inside a `try/catch` → the WHOLE route group 404s when Live TV is unconfigured. `GET /api/v1/auth/me`, `GET /api/v1/me/servers` (hub only; direct server 404s it), and `GET /health` (public, no auth) are NOT admin-gated. UUID ids path directly (no `UrlEncode`).
- **[convention]** Wire each new read/action through THREE coupled edits, op strings identical across all: a typed ApiClient method, an `else if req.op = "<op>"` branch in `components/ApiTask.brs`, and the scene's `m.apiTask.request = { op: "<op>" }`. Bodyless mutations go through `m.request("PUT"/"DELETE"/"POST", path, invalid)`.
- **[convention]** Cross-component callable subs MUST be declared in the target component's `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and bsc does NOT catch it. A scene a PARENT creates+appends+focuses and signals back via an OBSERVED FIELD (`loginSucceeded`/`connected`/`serverPicked`/`hubDetected`) needs NO interface fn. Each new component `.xml` must ALSO `<script>`-include its full source closure (Storage+Utilities+ApiClient+AppContext+own .brs) — component scope does NOT auto-include `pkg:/source`.
- **[gotcha]** `pos` is a RESERVED builtin in BrightScript — bsc rejects it as an identifier (BS1045 "Cannot use reserved word 'pos'" / BS1147 "can only be used as a function call"). It is NOT obviously reserved, so a loop cursor named `pos` compiles in your head but fails the gate. Rename to `cur`/`idx`. Other lib-builtin names (`tab`, `line_num`) are similarly reserved.
- **[gotcha]** BrightScript has NO infix `xor` operator (confirmed via Roku docs). `a xor b` parses but is wrong/unavailable for byte masking — compose it: `XorByte(a,b) = ((a OR b) AND NOT (a AND b)) AND 255` (the `AND 255` masks back to a single byte). Needed for any RFC6455 WebSocket client-frame masking.
- **[gotcha]** A component `<script>` closure must include ONLY what that component actually calls — including a convenience module pulls in ITS dependencies too. `AppContext.brs` calls `ApiClient(...)`, so listing `AppContext.brs` in a component XML without ALSO listing `ApiClient.brs` makes bsc fail with `BS1140: Cannot find function 'ApiClient'` scoped to that component. A Task driven purely by `config`/`command` fields needs neither — drop AppContext from its closure rather than dragging in ApiClient.
- **[gotcha]** `roStreamSocket` is PLAINTEXT TCP only — NO TLS — so a hand-rolled WebSocket can speak `ws://` only, never `wss://`. Socket I/O must live in a long-lived Task (off the render thread) on a SHARED `roMessagePort` receiving BOTH `roSocketEvent` and the observed `command` `roSGNodeEvent`; `wait(timeoutMs, port)` returning invalid is the periodic tick. THREAD RULE: the Task may only READ `config`/`command` and WRITE `event`/`connectionState` — never touch UI/parent nodes; only assoc/string/number cross the field boundary.
- **[gotcha]** Reading the handshake/socket byte stream via `chunk.ToAsciiString()` + `FromAsciiString()` MANGLES bytes ≥0x80 (multi-byte UTF-8 round-trip loss) — fatal when the first WS frame arrives in the same TCP segment as the `\r\n\r\n` terminator. Accumulate in an `roByteArray`, find the terminator by bytes (0x0D 0x0A 0x0D 0x0A), ASCII-decode ONLY the header slice, and append the byte remainder directly to the frame buffer — never via a String.
- **[gotcha]** A Boolean deep-copied across the Task→scene field boundary commonly boxes as `"roBoolean"`, not `"Boolean"` — `type(x)="Boolean"` alone silently never matches. Accept both `"Boolean" or "roBoolean"`. (Mirrors the numeric `roInt`/`Integer` family split.)
- **[gotcha]** ms↔seconds is a real boundary bug source: SyncPlay/wire positions are MILLISECONDS, Roku Video `position`/`seek` are SECONDS — convert (÷1000 inbound apply, ×1000 outbound). Build outbound ms as a LongInteger (`Int(pos# * 1000.0)`, `0&` literals) to avoid 32-bit overflow; `NowMs()` = `dt.AsSeconds()*1000& + dt.GetMilliseconds()` with the `&` literal.
- **[gotcha]** Do NOT both hand-implement/hand-edit a slice in the coordinator AND delegate the SAME slice to subagent(s) — they race / produce no-op duplicate work, AND never spawn TWO identical agents for one job. This recurs EVERY session (F9b, F10, F11b, F11c, F12a, F12b, and AGAIN in F13): the coordinator hand-wrote ALL source + hand-appended the worklog implementation-log AND spawned TWO identical general-purpose authors; then hand-appended the reviewer findings (`cat >>` heredoc) AND spawned TWO identical code-reviewers. Decide ONCE up front per slice (impl, review, AND docs): delegate OR do it inline, never both — and never spawn duplicate/parallel agents for one job.
- **[pattern]** Verify a slice with `npx -y brighterscript@0.72.5 --project bsconfig.json`; success prints only Parsing/Validating timing lines (confirm exit 0). bsconfig globs `components/**/*.{brs,xml}` + `source/**/*.brs` (NOT `tests/**`), so NEW component files are picked up with no config change, but deleting a `source/` factory leaves dangling refs in `tests/*.test.brs` uncaught — grep `tests/` and `git rm` orphaned `*.test.brs`. bsc + an independent reviewer are the ONLY quality bar — CI is informational and the device is unavailable.

- **[gotcha]** ApiClient getter return-shapes are INCONSISTENT — check the source before consuming. `getLibraries()`/`getItem()` UNWRAP to the bare array/object; ALL admin getters and `getMyServers`/`getCollections`/`getFavorites`/`getChannels`/`getGuide`/`getSyncPlayGroups` return the WHOLE envelope. Copying a sibling scene's access for a differently-shaped getter yields a silently EMPTY list.

Read the verified server contract in the slice worklog for exact key/casing before reading any field. Routes: the dead client hub code used the WRONG relay path `/api/v1/relay/{id}`; the REAL hub proxy is `/api/v1/servers/{id}/proxy/{path:.*}` — verify against `phlix-hub` source, not existing client code.
- **[gotcha]** The hub relay proxy registers ONLY `GET`/`POST`, so client `PUT`/`DELETE` (rating set, favorites-remove, session-end on logout) and WebSocket upgrades (hub strips `upgrade`) don't reach the server in hub mode. Treat non-GET/POST verbs AND SyncPlay/WS as a known hub-mode limitation — gate those features off in hub mode with a friendly `ShowErrorDialog`; build to direct mode.
- **[gotcha]** In hub mode `GetApiClient()` returns the RELAY base (`{hub}/api/v1/servers/{id}/proxy`) once `connection_kind="hub"` + `active_server_id` set. Any call that must hit the BARE hub/connect endpoint — login, the `/me/servers` probe, boot session validation (`/auth/me`) — MUST build from `GetHubApiClient()` (bare `server_url`), NOT `GetApiClient()`. A silent misroute bsc can't catch.

Bodyless mutations go through `m.request("PUT"/"DELETE"/"POST", path, invalid)`. To hit an endpoint OUTSIDE the `/api/v1` prefix (e.g. `/health`), add a dedicated ApiClient method with its OWN `roUrlTransfer` — `request()`/`sendRaw` force-prepend `/api/v1`.
- **[convention]** Cross-component callable subs MUST be declared in the target component's `<interface>` as `<function name="..."/>` (bsc does NOT catch a missing one). A scene a PARENT creates+appends+focuses and signals back via an OBSERVED FIELD (`loginSucceeded`/`serverPicked`/`hubDetected`) needs NO interface fn. Each new component `.xml` must `<script>`-include its full source closure — component scope does NOT auto-include `pkg:/source`.
- **[convention]** New scenes/keys use `function OnKeyEvent(key as String, press as Boolean) as Boolean`; pair EVERY `ObserveField` with `UnObserveField` in `Teardown`/`ClosePlayer` (list selections, every button, the apiTask `response` field, the syncTask `event` field). Back → `Teardown()` + `m.top.Close()` (or eat `back` for no-back-out screens). `LibraryScene`'s older `sub OnKeyEvent ... as Boolean` is the exception — don't copy it.
- **[pattern]** When integrating an OPTIONAL feature into a shipped scene, keep the default path byte-unchanged: init all feature state inert, create the worker Task/observers LAZILY on first activation (not in `Init`), and broadcast/apply ONLY at the user-input layer (key handlers) — NOT from a state observer like `OnPlayerStateChange`, which also fires for remote-applied and non-user transitions and causes feedback loops. Use an `m.applyingRemote` guard so a remote-driven change never rebroadcasts.

There is NO CHANGELOG.md in the roku repo.
