# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Don't grep-count `if` vs `end if` in `.brs` files as a brace-balance sanity check — BrightScript single-line `if … then …` statements and `else if` clauses have no matching `end if`, so a healthy file shows far more `if` than `end if` (e.g. PlayerScene.brs: 35 vs 23). A mismatch is NOT a syntax error.
- **[gotcha]** Local clones of the native-client repos under `/home/sites/phlix/` (roku, mobile, windows) can be on a divergent local `master` (same commit messages, different SHAs from a prior history rewrite) while `tizen` stays in sync. Branching a feature off local `master` bases the PR on commits origin lacks → `gh pr merge` fails with phantom merge conflicts even for a one-line change. Branch from origin instead: `git fetch origin && git checkout -B <branch> origin/master`.
- **[pattern]** After editing a `.brs`/`.xml` change in this repo, `make validate-xml` is the only verification that actually exits non-zero on failure (`make lint`/`make test` never fail). Run it as the real gate; treat `make lint` output as informational only.
- **[env]** There IS now a real BrightScript compile gate: `npx bsc --project bsconfig.json` (brighterscript, pinned to 0.72.5 in devDependencies). It exits non-zero on any error and CI `lint.yml` runs it WITHOUT `|| true`. This supersedes the old "no compiler" note for verification — run `bsc` as the authoritative gate after any `.brs`/`.xml` change, before `make validate-xml`.
- **[fix]** If `npx bsc --project bsconfig.json` fails with `npm error could not determine executable to run`, the `bsc` bin alias isn't resolvable in this sandbox — invoke the full package with `-y`: `npx -y brighterscript@0.72.5 --project bsconfig.json`. Filter output with `2>&1 | grep -E "error|warning|Found [0-9]"` and read `${PIPESTATUS[0]}` for the real exit code.
- **[gotcha]** SceneGraph component scopes do NOT auto-include `pkg:/source/`. Each component `.xml` must explicitly `<script type="text/brightscript" uri="pkg:/source/..."/>`-include the TRANSITIVE CLOSURE of source files whose functions its `.brs` calls, or `bsc` fails BS1140 ("cannot find function") and it crashes at runtime. Including the same source file in many components is the blessed, non-conflicting pattern. Example: any component calling `GetApiClient` must include `Storage.brs + Utilities.brs + ApiClient.brs + AppContext.brs`.
- **[gotcha]** BrightScript subs/functions that `return` no value must be annotated `as Void` or `bsc` fails BS1142 (bare-return). When adding/fixing object-literal methods in `source/lib` factories or scene `.brs`, append `as Void` to any handler that returns nothing.
- **[gotcha]** `roTimer` (`CreateObject("roTimer")`) is unusable inside SceneGraph (`bsc` BS1129). Use a SceneGraph `Timer` node instead: `m.top.CreateChild("Timer")`, set `.duration`/`.repeat`, `ObserveField("fire", ...)`, then `.control = "start"`/`"stop"`. On teardown also `UnobserveField("fire")` + `m.top.RemoveChild(timer)` or the node/observer leaks.
- **[gotcha]** `const` is a BrighterScript-only keyword and is INVALID in the plain BrightScript this repo ships — it will crash the app at launch. Roku compiles ALL of `source/` at launch, so a syntax error in ANY source file (e.g. `const`, an end-sub/end-function mismatch, or a function `declared more than once` in source scope) = total launch failure, not just a broken module. Delete or fix dead/invalid source files rather than leaving them.
- **[gotcha]** A SceneGraph interface `<field>` cannot have `type="func"` (`bsc` BS1068). To trigger cross-scene navigation, declare a `type="boolean"` field, set it `true` from the child scene, and `ObserveField` it from the parent — don't try to pass a function through a field.
- **[convention]** BrightScript has no global variables, only global functions. Shared app state (the ApiClient, server URL) is exposed via source-scope accessor functions in `source/lib/AppContext.brs` (`GetApiClient()`, `GetServerUrl()`) that rebuild a transient client and restore token/session from `Storage`. Scenes/managers must NOT reference bare globals like `api`/`authManager` — those resolve to `invalid` at runtime; build `m.api` in `Init` via `GetApiClient()` and pass it into managers.
- **[pattern]** After editing a `.brs`/`.xml` change in this repo, `make validate-xml` is the only `make` verification that actually exits non-zero on failure (`make lint`/`make test` never fail). Run it as a real gate; treat `make lint` output as informational only.
- **[convention]** Components now live in top-level `components/` (git-mv'd out of `source/components/`); `bsconfig.json` globs `manifest + source/**/*.brs + components/**/*.{brs,xml} + images` and `make package` ships `manifest source components images`. Keep new scene files under `components/`, not `source/components/`.
