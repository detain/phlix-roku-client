# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** Each NEW component `.xml` must `<script>`-include its FULL source closure IN ORDER (`Storage`, `Utilities`, `ApiClient`, `AppContext`, then its own `pkg:/components/<Scene>.brs`) — a component scope does NOT auto-include `pkg:/source`. A missing include is a runtime "function not found" that `bsc` does NOT catch.
- **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` from another scene require declaration. Verify caller arg arity/order matches the callee signature.
- **[convention]** Stringify ints the repo way: `str(Int(x)).trim()` (matches `LibraryScene` `str(item.year).trim()`, `Utilities` EpisodeCaption, ApiClient `str(limit).trim()`). Before committing an appended helper, check the file's existing EOF (e.g. `tail -c | xxd`) and match it — `Utilities.brs` has NO trailing newline on master, so preserve that to keep the diff minimal.
- **[pattern]** Verify a scene against the bsc gate with `npx brighterscript@0.72.5 --project bsconfig.json` and grep the log for `error|warn` (EXIT=0 + "clean" = pass). This is the ONLY real static gate — `make lint`/`make test`/CI never fail.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript runtime type-mismatch ("Operator not allowed on these types") and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (e.g. `date_taken_year`, a year), branch on `type(x) = "String" or type(x) = "roString"` (string path may compare `<> ""`) else coerce via `Int(x)` and check `> 0` — mirror the repo's `str(Int(album.year)).trim()` idiom. Only `<> ""`-guard fields KNOWN to be strings.
- **[pattern]** To add a slideshow/auto-advance, create a repeating `Timer` IN CODE (SearchScene idiom: `m.top.CreateChild("Timer")`, `.duration`, `.repeat = true`, `.ObserveField("fire", handler)`, `.control = "start"/"stop"`). A manual nav key should restart it (`stop` then `start`) to reset the dwell; guard the advance with `count > 1` (no mod-by-zero / no slideshow over one item). A scene that previously observed NOTHING must GAIN a `Teardown` (stop + `UnObserveField("fire")`) called on Back BEFORE `Close` once it observes the Timer's `fire`.
- **[pattern]** EXIF for a photo is ALREADY on each list item's `metadata` (no getPhoto round-trip). Build a display summary with a PURE Utilities helper that guards `exif = invalid` AND `type(exif) <> "roAssociativeArray"` → "", then guards EACH key with `DoesExist` + `<> invalid` (+ a TYPE-aware emptiness check, never a blind `<> ""` on numeric fields). Return "" when nothing present so the caller can show a placeholder.
- **[gotcha]** Do NOT both delegate a slice to a subagent AND hand-implement the same slice in the coordinator — they race / produce no-op duplicate work. Decide ONCE up front: delegate the impl OR do it inline, never both.
- **[gotcha]** A custom focus state machine over sibling SceneGraph nodes must CONSUME (`handled=true`) every directional key while a zone is entered, AND check intra-zone nav FIRST/gated on the current zone (`m.currentRail = "search"`) so those keys still bubble to grids in OTHER zones. Centralize zone re-entry in a helper (e.g. `FocusHeaderZone()`). When growing a 2-button header to 3+, make Left/Right an explicit cycle that STOPS at the ends (never wraps) and add the new column to BOTH the nav branches and the focus helper. Framework key bubbling between Buttons/PosterGrids is DEVICE-UNVERIFIABLE — own the input defensively and flag it for device QA.
- **[convention]** Components live in top-level `components/` (git-mv'd out of `source/components/`); `bsconfig.json` globs `manifest + source/**/*.brs + components/**/*.{brs,xml} + images`, and `make package` zips `manifest source components images`. Keep new scene files under `components/`, not `source/components/`. (CLAUDE.md still says `source/components/` — it is stale; trust the actual tree.)
- **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` (e.g. HomeScene self-creating MusicScene/CollectionsScene) needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` from another scene require declaration (e.g. CollectionScene's `LoadCollection`). Verify caller arg arity/order matches the callee signature.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript runtime type-mismatch ("Operator not allowed on these types") and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String, branch on `type(x) = "String" or type(x) = "roString"` (string path may compare `<> ""`) else coerce via `Int(x)` and check. Only `<> ""`-guard fields KNOWN to be strings.
- **[gotcha]** The same crash applies at the CALL site: passing a possibly-non-String JSON field into a sub/function param typed `as String` (e.g. `SetStatus(collection.name)`) blows up at runtime if the value isn't a String, and `bsc` won't flag it. Narrow with `type(x) = "String" or type(x) = "roString"` BEFORE the call, even when the contract claims the field is always a String.
- **[convention]** An integer field like `year` frequently arrives as `0` (DB default / unparsed) — it is `<> invalid` but not a real value, and `str(Int(year)).trim()` renders a bogus "0" caption. Format first, then skip the assignment when the result is `"0"` (mirror `Utilities.AlbumCaption`).
- **[pattern]** To add a slideshow/auto-advance, create a repeating `Timer` IN CODE (`m.top.CreateChild("Timer")`, `.duration`, `.repeat = true`, `.ObserveField("fire", handler)`, `.control = "start"/"stop"`). A manual nav key should restart it (`stop` then `start`); guard advance with `count > 1`. A scene that previously observed NOTHING must GAIN a `Teardown` (stop + `UnObserveField("fire")`) called on Back BEFORE `Close`.
- **[pattern]** When adding a browse screen that mirrors an existing one, copy the closest template's grid/list-build + index-guarded type-routed selection idiom verbatim (LabelList-of-names ⟵ MusicScene; PosterGrid-of-items ⟵ LibraryScene/FavoritesScene). Back the CURRENT list with `m.rows`/`m.items`/`m.collections` so `itemSelected` index maps to the right object, gate each list field on `type(x) = "roArray"` before iterating (reset to `[]` first), and pair EVERY `ObserveField` in `Teardown`. `back` calls `Teardown()` + `m.top.Close()`.
- **[convention]** Server `items` are NOT always MediaItemShaper-shaped: collection-item rows from `GET /collections/{id}` carry id/name/type top-level but poster_url/overview/year under `metadata.*` (which MAY be a non-assoc string — read it only behind `type(meta) = "roAssociativeArray"`). Flatten each row through a `Normalize*` helper in `Utilities.brs` before feeding a grid; keep `type` top-level so series→SeriesScene / season→SeasonScene routing still works.
- **[convention]** Collection read routes (`GET /api/v1/collections`, `/collections/{id}`) are currently UNAUTHENTICATED server-side (no AuthMiddleware — a known upstream gap; the client still sends Bearer/X-Phlix headers). `/collections/{id}` EMBEDS its items as `{collection, items, total}` — there is NO `/collections/{id}/items` route. Endpoints return the WHOLE envelope (mirror getFavorites/getAlbums); the scene reads the named key. A collection id is a UUID → path directly (no `UrlEncode`, like getItem).
- **[gotcha]** Photo routes are `GET /api/v1/photo/*` — SINGULAR (`/photo/albums`, `/photo/albums/{id}`), NOT `/photos/`. JSON routes are Bearer-gated and `library_id` is REQUIRED (400 if omitted). Image-byte routes (`/thumbnail`,`/full`) take a SIGNED-URL token, NOT a Bearer; drop signed absolute URLs VERBATIM into `HDPosterUrl`/`Poster.uri` with `pkg:/images/placeholder.png` as the invalid/empty fallback.

- **[convention]** New scenes use `function OnKeyEvent(...) as Boolean` (FavoritesScene/MusicScene convention); `LibraryScene.brs` uses the older `sub OnKeyEvent ... as Boolean` — don't copy the older form.
