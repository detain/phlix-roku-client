# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Do NOT both hand-implement/hand-edit a slice in the coordinator AND delegate the SAME slice to subagent(s) — they race / produce no-op duplicate work. This recurs EVERY session (F11b, F11c, F9b, F10, F12a impl, and AGAIN in the F12a docs wrap-up): the coordinator hand-wrote ALL README.md + CLAUDE.md edits AND hand-appended the worklog Scribe section (via `cat >>` heredoc), THEN spawned TWO identical `scribe` agents for the already-finished doc work — same trap, different agent type (general-purpose / code-reviewer / scribe). Decide ONCE up front per slice (impl, review, AND docs): delegate OR do it inline, never both — and never spawn duplicate agents (or two at once) for one job.
- **[convention]** Doc updates for a new scene go in README.md (rewrite the relevant flow prose, add the scene to the Project-Structure component list, fix stale troubleshooting steps) and CLAUDE.md (architecture/flow sections) — NOT DEVELOPER.md (lib/manager-focused). There is NO CHANGELOG.md in the roku repo — do not create one. `phlix-docs` (`docs/clients/roku.md`, `docs/dev/client-roku.md`) is a separate end-user/pre-F0b-build-spec repo and is out of scope unless the slice explicitly names it.
- **[gotcha]** README.md / CLAUDE.md carry STALE pre-F0b Emby-era prose ("Device profile is load-bearing", `/Items/{id}/PlaybackInfo`, `ApiClient.deviceProfile`, hardcoded `localhost:8096` fallback, "server URL comes from the login flow / Settings page"). F0b removed the device profile + Emby routes (canonical `/api/v1` now); F12a moved server-URL entry to the first-run ConnectScene. Fix these in passing when you touch the surrounding section — don't trust existing doc prose as current.
- **[convention]** When staging a feature commit, `git add` the specific source dirs/files (`git add components/ source/ <files>`) and `git reset -q HEAD .claude/` — do NOT `git add -A`/`git add .` — so untracked tooling dirs like `.claude/skills/` stay out; verify with `git show --stat HEAD | grep -c '.claude'` → 0. `gh pr create` will still warn "1 uncommitted change" for that untracked dir — harmless.
- **[pattern]** Verify a slice with the bsc gate `npx -y brighterscript@0.72.5 --project bsconfig.json`; on success it prints only "Parsing/Validating finished" timing lines. Confirm with `echo "exit: ${PIPESTATUS[0]}"` (exit 0) rather than scanning stdout. bsconfig globs `components/**/*.{brs,xml}` + `source/**/*.brs`, so NEW component files are picked up with NO manifest/bsconfig change. bsc + an independent reviewer are the ONLY quality bar — CI is informational and the device is unavailable.
- **[pattern]** To hit a server endpoint OUTSIDE the `/api/v1` prefix (e.g. the public `/health`), do NOT route through `request()`/`sendRaw` — they force-prepend `/api/v1`. Add a dedicated ApiClient method with its OWN `roUrlTransfer` to `m.baseUrl + "/health"`. A body-only probe can use SYNC `GetToString()` with a short `SetTimeout` (safe on the ApiTask thread).
- **[convention]** Wire each new read/action through THREE coupled edits, op strings identical across all: a typed ApiClient method (`m.request("GET", "/admin/...", invalid)` or a dedicated transport), an `else if req.op = "<op>"` branch in `components/ApiTask.brs` (`result.ok = (result.data <> invalid)` or a validator helper), and the scene's `m.apiTask.request = { op: "<op>" }`. Bodyless mutations go through `m.request("PUT"/"DELETE"/"POST", path, invalid)`. `sendRaw` prepends `/api/v1`.
- **[gotcha]** Guarding a possibly-numeric/bool JSON field with `<> ""` raises a BrightScript Integer-vs-String type-mismatch and CRASHES the render — bsc does NOT catch it. For any field the server contract does NOT type as String (`year`, `progress_percent`, `item_count`, `is_admin`, `is_active`, `rating`, `start_time`, `duration`, `priority`, channel `number`, a health `version`): guard `DoesExist`+`<> invalid` ONLY, then coerce via `str(Int(x)).trim()` (`Int()` on a String can also RAISE — type-guard the numeric family first). A possibly-string field that IS safe to compare (health `status="ok"`) still needs `type(s)="String" or "roString"` before the `=`. Same at the CALL site: a JSON value passed into a param typed `as String` (id in a URL path) must be stringified BEFORE crossing.
- **[gotcha]** `is_admin`/`is_active`/`pin_required_for_admin` arrive from JSON as TINYINT (0/1, sometimes Boolean) — read truthy flags ONLY via `Utilities.IsAdminUser(user)` (is_admin) or the generic `IsTruthyFlag(container,key)`. NEVER compare with `<> ""`.
- **[gotcha]** A 401/403/400/404/500 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with no expected data key. Do NOT assume an auth/validation/error failure yields `resp.ok = false`. Always read the SPECIFIC expected key (`resp.data.DoesExist("profiles"/...)` + `type()="roArray"` for lists) and for mutations use a `MessageOf(resp)` message-else-error reader.
- **[gotcha]** ApiClient getter return-shapes are INCONSISTENT — check the source before consuming. `getLibraries()`/`getItem()` UNWRAP to the bare array/object, whereas ALL admin getters and `getCollections`/`getFavorites`/`getAlbums`/`getGuide`/`getRecordings`/`getSeriesRules`/`getChannels` return the WHOLE envelope. Copying a sibling scene's access for a getter with a different shape yields a silently EMPTY list.
- **[gotcha]** Server JSON field-name landmines bsc can't catch: some list rows have NO top-level `id` — a live-TV series rule's identifier is `rule_id`. Read the verified server contract in the slice worklog for the exact key before reading any `.id`. The roku/mobile dead hub code uses the WRONG relay path `/api/v1/relay/{id}`; the REAL hub proxy path is `/api/v1/servers/{id}/proxy/{path:.*}` — verify routes against `phlix-hub` source, not against existing client code.
- **[convention]** `GET /api/v1/admin/*` is gated by `AdminMiddleware` (requires `is_admin=1` AND `status='active'`; non-admin→403, no-token→401). `/admin/livetv/*` is registered inside a `try/catch` → the WHOLE route group 404s when Live TV is unconfigured. `GET /api/v1/auth/me` and `GET /health` (hub + server, public, no auth) are NOT admin-gated. UUID ids path directly (no `UrlEncode`).
- **[convention]** Cross-component callable subs MUST be declared in the target component's `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and bsc does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` (or signals back via an OBSERVED FIELD like `loginSucceeded`/`connected`) needs NO interface fn — only `scene.Method(...)` entry-points across the boundary do. Each new component `.xml` must ALSO `<script>`-include its full source closure (Storage+Utilities+ApiClient+AppContext+own .brs) — component scope does NOT auto-include `pkg:/source`.
- **[convention]** New scenes use `function OnKeyEvent(key as String, press as Boolean) as Boolean`; back → `Teardown()` + `m.top.Close()` (or eat `back` returning handled=true for no-back-out screens like Login/Connect). Pair EVERY `ObserveField` with `UnObserveField` in `Teardown` (list itemSelected/itemFocused, every button's buttonSelected, AND the apiTask `response` field). `LibraryScene.brs`'s older `sub OnKeyEvent ... as Boolean` form is the exception — don't copy it.
- **[gotcha]** In hub mode `GetApiClient()` returns the RELAY base (`{hub}/api/v1/servers/{id}/proxy`) as soon as `connection_kind="hub"` AND `active_server_id` is set (via `GetMediaBaseUrl()`). Any call that must hit the BARE hub/connect endpoint — login (`POST /auth/login`), the `/me/servers` hub-detection probe, and boot session validation (`/auth/me`) — MUST build its client from `GetHubApiClient()` (bare `server_url`), NOT `GetApiClient()`. LoginScene.Init binds `m.api = GetHubApiClient()` unconditionally so re-login after the hourly hub-token expiry doesn't POST credentials through the relay, where the proxy's own AuthMiddleware 401s the expired token before it ever tunnels. A scene left on the relay-bound `GetApiClient()` for a connect-endpoint call is a silent misroute bsc can't catch.
- **[gotcha]** The hub relay proxy (`phlix-hub` `Application.php` `/api/v1/servers/{id}/proxy/{path:.*}`) registers ONLY `GET` and `POST`. In hub mode every scene's ApiClient is relay-bound, so client `PUT`/`DELETE` calls (`PUT /media/{id}/rating`, `DELETE /media/{id}/favorite|rating`, `DELETE /sessions/{id}` on logout) 404/405 at the hub and never reach the server. Treat non-GET/POST verbs as a known hub-mode limitation — don't assume a mutation that works in direct mode survives the relay.
- **[gotcha]** `tests/**` is NOT in `bsconfig.json`'s `files` globs (only `source/**` + `components/**`), so the bsc gate does NOT catch dangling references in `tests/*.test.brs` after you delete the `source/` factory they exercise. When removing a lib/module, grep `tests/` for callers and `git rm` the orphaned `*.test.brs` too, then `rmdir` the now-empty dirs — don't rely on bsc or a self-flagged "left for follow-up" note.
- **[convention]** Hub-mode persistence keys: `connection_kind` ("hub"/"direct", absent→treated as direct), `active_server_id`, `active_server_name`. On logout, `Storage.delete` all three but KEEP `server_url` (the connect endpoint) so the user isn't re-prompted for it. Boot gate order in `PhlixApp.Init`: `IsServerConnected()` → `GetConnectionKind()="hub"` (validate via `GetHubApiClient` then `GetActiveServerId()<>""` ? Home : ServerPicker) → else direct `checkAuth()`.
