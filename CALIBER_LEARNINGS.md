# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** `Int()` on a String can raise at runtime. When coercing a JSON field that MIGHT arrive as Boolean/Integer/Float (e.g. `is_admin`, a TINYINT 0|1 that could deserialize as bool or int), type-guard the numeric family (`type(x) = "Boolean"/"Integer"/"Float"/"Double"`) BEFORE calling `Int()` — never let a String reach `Int()`. Mirror this in a dedicated helper like `IsAdminUser` rather than inlining a bare `Int()`.
- **[gotcha]** The same crash applies at the CALL site: passing a possibly-non-String JSON field into a sub/function param typed `as String` (e.g. `SetStatus(collection.name)`) blows up at runtime if the value isn't a String, and `bsc` won't flag it. Narrow with `type(x) = "String" or type(x) = "roString"` BEFORE the call.
- **[gotcha]** A 401/403 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with `result.data = {error,code}`. Do NOT assume an auth failure yields `resp.ok = false`. Make the empty-render safe by having `ExtractData` return `[]` when the EXPECTED data key is absent / not an `roArray` (not by trusting `ok=false`). Only the cleared-token refresh-fail 401 path yields invalid.
- **[pattern]** A conditional/hidden header button (`visible="false"`, revealed only when a flag like `m.isAdmin` is set after a `getMe` read): a `SetFocus(true)` on a hidden node is a runtime defect bsc won't catch. Guard the directional nav INTO that button's column with the SAME flag that reveals it (`m.isAdmin and m.button <> invalid`), and make the focus-helper branch for that column reachable ONLY after that guarded nav set the column state. Growing a 2/3-button header to N: make Left/Right an explicit cycle that STOPS at the ends (never wraps) and add the new column to BOTH the nav branches and the focus helper.
- **[pattern]** When inserting a GATING call at the FRONT of a serialized load chain (e.g. `getMe` before `getLibraries` → `getContinueWatching`), the new response handler MUST continue the chain (call the next `Load*`) OUTSIDE the `if resp.ok` block — the ok-guard should gate ONLY the new feature flag, not the rest of the chain. Otherwise a failed/forbidden gating call dead-ends the whole screen for non-privileged users. Keep single `control="run"` discipline: each op fires the next only from its own branch in `OnApiResponse`, never two outstanding.
- **[gotcha]** Do NOT both delegate a slice to a subagent AND hand-implement the same slice in the coordinator — they race / produce no-op duplicate work. This recurs across sessions: in F11a the coordinator hand-WROTE a full "## CODE REVIEW" worklog section AND THEN spawned code-reviewer agents to re-derive the same findings (and spawned TWO identical reviewers at once). Decide ONCE up front per slice: delegate the review/impl/docs OR do it inline, never both — and never spawn duplicate agents for one job.
- **[pattern]** The clean way to combine subagent review with coordinator edits: instruct the review subagent "Do NOT modify any code — review only" and have it APPEND findings to the worklog; the coordinator then applies fixes itself and re-runs the bsc gate. On a device-only-unverifiable target, fixing even LOW findings (e.g. a stale mechanism comment) is cheap insurance.
- **[pattern]** When adding a browse/list screen that mirrors an existing one, copy the closest template's grid/list-build + index-guarded type-routed selection idiom verbatim (LabelList-of-names ⟵ MusicScene/CollectionsScene; PosterGrid-of-items ⟵ LibraryScene/FavoritesScene). Back the CURRENT list with `m.rows`/`m.items` so `itemSelected` index maps to the right object, gate each list field on `type(x) = "roArray"` before iterating (reset to `[]` first), and pair EVERY `ObserveField` in `Teardown`. `back` calls `Teardown()` + `m.top.Close()`.
- **[pattern]** EXIF/metadata for a list item is ALREADY on each row's `metadata` (no per-item round-trip). Build a display summary with a PURE Utilities helper that guards `meta = invalid` AND `type(meta) <> "roAssociativeArray"` → "", then guards EACH key with `DoesExist` + `<> invalid` (+ a TYPE-aware emptiness check). Return "" when nothing present so the caller can show a placeholder.
- **[convention]** Server `items` are NOT always MediaItemShaper-shaped: collection-item rows carry id/name/type top-level but poster_url/overview/year under `metadata.*` (which MAY be a non-assoc string — read it only behind `type(meta) = "roAssociativeArray"`). Flatten each row through a `Normalize*` helper in `Utilities.brs` before feeding a grid; keep `type` top-level so series→SeriesScene / season→SeasonScene routing still works.
- **[convention]** An integer field like `year` frequently arrives as `0` (DB default) — it is `<> invalid` but not a real value. Format first, then skip the assignment when the result is `"0"` (mirror `Utilities.AlbumCaption`).
- **[convention]** Stringify ints the repo way: `str(Int(x)).trim()` (matches `LibraryScene`/`Utilities`/`ApiClient`/`CollectionScene`/`SeriesScene`). Before committing an appended helper, check the file's existing EOF (e.g. `tail -c | xxd`) and match it — `Utilities.brs` has NO trailing newline on master.
- **[convention]** New scenes use `function OnKeyEvent(...) as Boolean` (FavoritesScene/MusicScene/AdminScene/DashboardScene convention); `LibraryScene.brs` uses the older `sub OnKeyEvent ... as Boolean` — don't copy the older form.
- **[gotcha]** Photo routes are `GET /api/v1/photo/*` — SINGULAR (`/photo/albums`), NOT `/photos/`. JSON routes are Bearer-gated and `library_id` is REQUIRED (400 if omitted). Image-byte routes take a SIGNED-URL token, NOT a Bearer; drop signed absolute URLs VERBATIM into `HDPosterUrl`/`Poster.uri` with `pkg:/images/placeholder.png` as the fallback.
- **[convention]** Collection read routes (`GET /api/v1/collections`, `/collections/{id}`) and the `/admin/dashboard/*` reads are device-only-verifiable. `/collections/{id}` EMBEDS its items as `{collection, items, total}` — there is NO `/collections/{id}/items` route. Endpoints return the WHOLE envelope; the scene reads the named key. A collection id is a UUID → path directly (no `UrlEncode`).
- **[convention]** `GET /api/v1/admin/*` is gated by `AdminMiddleware` (requires `users.is_admin=1` AND `status='active'`). `GET /api/v1/auth/me` is AUTH-gated (NOT admin) and carries `is_admin`/`status` — use it to gate admin UI client-side.
- **[env]** Per-slice specs, the VERIFIED server contract, and worklogs live OUTSIDE the repo at `/home/sites/phlix/steps/<SLICE>-roku-*.worklog.md` (e.g. `F11a-roku-admin-entry-dashboard.worklog.md`). Read the slice worklog FIRST: it carries the confirmed route table, auth status, and response shapes scouted from `phlix-server`.
- **[convention]** When documenting a new scene, update README.md's "Project Structure" scene inventory + the API Endpoints table — NOT DEVELOPER.md (which documents the GENERIC `m.api.request(...)` pattern and is lib/manager-focused). There is NO CHANGELOG.md in this repo — do not create one.

- **[convention]** Components live in top-level `components/` (git-mv'd out of `source/components/`); `bsconfig.json` globs `manifest + source/**/*.brs + components/**/*.{brs,xml} + images`, and `make package` zips `manifest source components images`. - **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` (e.g. HomeScene→AdminScene→DashboardScene) needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` from another scene require it. Verify caller arg arity/order matches the callee signature.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript runtime type-mismatch and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (e.g. `date_taken_year`, `progress_percent`, `item_count`, a year), branch on `type(x) = "String" or type(x) = "roString"` (string path may compare `<> ""`) else coerce via `str(Int(x)).trim()` and check `> 0`. Only `<> ""`-guard fields KNOWN to be strings.
