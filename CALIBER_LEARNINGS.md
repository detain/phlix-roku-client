- **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` (e.g. HomeScene→AdminScene→DashboardScene) needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` from another scene require it. Verify caller arg arity/order matches the callee signature.
- **[gotcha]** Guarding a possibly-numeric JSON field with `<> ""` (a String literal) raises a BrightScript runtime type-mismatch and CRASHES the render — `bsc` does NOT catch it. For any field the server contract does NOT type as String (e.g. `date_taken_year`, `progress_percent`, `item_count`, a year), branch on `type(x) = "String" or type(x) = "roString"` (string path may compare `<> ""`) else coerce via `str(Int(x)).trim()` and check `> 0`. Only `<> ""`-guard fields KNOWN to be strings.
- **[gotcha]** The same crash applies at the CALL site: passing a possibly-non-String JSON field into a sub/function param typed `as String` blows up at runtime if the value isn't a String, and `bsc` won't flag it. Narrow with `type(x) = "String" or type(x) = "roString"` BEFORE the call.
- **[pattern]** A conditional/hidden header button (`visible="false"`, revealed only when a flag like `m.isAdmin` is set after a `getMe` read): a `SetFocus(true)` on a hidden node is a runtime defect bsc won't catch. Guard the directional nav INTO that button's column with the SAME flag that reveals it (`m.isAdmin and m.button <> invalid`). Growing a 2/3-button header to N: make Left/Right an explicit cycle that STOPS at the ends (never wraps) and add the new column to BOTH the nav branches and the focus helper.

- **[gotcha]** ApiClient getter return-shapes are INCONSISTENT — check the source before consuming. `getLibraries()` UNWRAPS and returns the bare ARRAY (consume as `resp.data` + guard `type(resp.data) = "roArray"`), whereas `getCollections()`/`getFavorites()`/`getAlbums()` return the WHOLE envelope (consume as `resp.data.collections` etc.). Copying a sibling scene's `resp.data.<key>` access for a getter that already unwrapped yields a silently EMPTY list. Verify with `grep -n "getLibraries\|getCollections\|getFavorites" source/lib/ApiClient.brs` and read the function body.
- **[convention]** Bodyless POST mutations go through `m.request("POST", path, invalid)` — `sendRaw` does `SetRequest("POST")` then `AsyncGetToString()` when `body = invalid`, issuing a real bodyless POST (NOT a GET). This is the proven pattern (`startTranscode`); reuse it verbatim for new enqueue-style admin actions (`scan`/`rescan`/`match-metadata`). Wire each as a new `ApiTask` op (`result.ok = (result.data <> invalid)`) AND a typed ApiClient method.
- **[pattern]** For a scene with multiple action buttons that each fire ONE serialized request: use a SINGLE ApiTask and an `m.pendingOp` guard (invalid = idle; mirrors HomeScene's `m.pendingResume`). Every entry point (`QueueJob`, `RefreshStatus`) bails when `m.pendingOp <> invalid`; in `OnApiResponse` clear `m.pendingOp = invalid` FIRST, THEN optionally chain a follow-up call (e.g. a status refresh after a queued job) so it runs as a fresh serialized request — never two `control="run"` outstanding.

- **[gotcha]** A 401/403 from the Phlix server returns a JSON error body `{error,code}`, so `ApiClient.request()` returns a NON-invalid AA → ApiTask sets `result.ok = true` with no expected data key. Do NOT assume an auth failure yields `resp.ok = false`. Make empty/error renders safe by checking the EXPECTED key (`resp.data.DoesExist(...)`) and degrading to a placeholder (`[]` / "Never scanned"), not by trusting `ok`.
