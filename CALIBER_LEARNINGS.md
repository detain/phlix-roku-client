# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[convention]** When staging a feature commit, `git add` the specific source dirs/files (`git add source/ components/ <files>`) — do NOT `git add .`/`git add -A` — so untracked tooling dirs like `.claude/skills/` stay out; verify with `git diff --cached --name-only | grep -q '.claude'`. If you do `git add -A`, unstage with `git reset HEAD .claude/`. `gh pr create` will still warn "1 uncommitted change" for that untracked dir — harmless.
- **[env]** Per-slice specs, the VERIFIED server contract, and worklogs live OUTSIDE the repo at `/home/sites/phlix/steps/<SLICE>-roku-*.worklog.md`. Read/author the slice worklog FIRST: it carries the confirmed route table, auth status, and response shapes scouted from `phlix-server`/`phlix-hub`/`phlix-mobile-client`. Don't guess the filename — `ls /home/sites/phlix/steps/ | grep -i <slice>` then Read it.
- **[pattern]** Verify a slice with the bsc gate `npx -y brighterscript@0.72.5 --project bsconfig.json`; on success it prints only "Parsing/Validating finished" timing lines (no error lines). Confirm with `echo "exit: ${PIPESTATUS[0]}"` (exit 0) rather than scanning stdout. bsconfig globs `components/**/*.{brs,xml}` + `source/**/*.brs`, so NEW component files are picked up with NO manifest/bsconfig change. bsc + an independent reviewer are the ONLY quality bar — CI is informational and the device is unavailable.
- **[pattern]** To hit a server endpoint OUTSIDE the `/api/v1` prefix (e.g. the public `/health`), do NOT route through `request()`/`sendRaw` — they force-prepend `/api/v1`. Add a dedicated ApiClient method with its OWN `roUrlTransfer` to `m.baseUrl + "/health"`. A body-only probe can use SYNC `GetToString()` (no message port) with a short `SetTimeout` — sync is safe because it runs on the ApiTask thread and only needs the body, not `GetResponseCode()` (the async-with-port idiom in sendRaw exists ONLY for refresh-on-401).
- **[gotcha]** ANY new `roUrlTransfer` must replicate the HTTPS cert idiom or https origins silently fail: `if Left(url,6) = "https:" then http.SetCertificatesFile("common:/certs/ca-bundle.crt") : http.InitClientCertificates()`. bsc does NOT catch its absence.
- **[pattern]** To probe/connect a candidate URL that is NOT yet persisted (first-run connect), pass the url in the ApiTask request and build a FRESH `ApiClient(req.url)` inside the op — NOT `GetApiClient()`, which binds to the old/absent persisted `server_url`. The throwaway client's ctor does no Storage read, so it stays clean.
- **[convention]** Wire each new read/action through THREE coupled edits, op strings identical across all: a typed ApiClient method (`m.request("GET", "/admin/...", invalid)` or a dedicated transport), an `else if req.op = "<op>"` branch in `components/ApiTask.brs` (`result.ok = (result.data <> invalid)`, or with a `HealthOk`/validator helper), and the scene's `m.apiTask.request = { op: "<op>" }`. Bodyless mutations go through `m.request("PUT"/"DELETE"/"POST", path, invalid)` — `request()`/`sendRaw` honor the verb and issue a real bodyless request when body=invalid. `sendRaw` prepends `/api/v1`.
- **[gotcha]** Guarding a possibly-numeric/bool JSON field with `<> ""` raises a BrightScript Integer-vs-String type-mismatch and CRASHES the render — bsc does NOT catch it. For any field the server contract does NOT type as String (`year`, `progress_percent`, `item_count`, `is_admin`, `is_active`, `rating`, `start_time`, `duration`, `priority`, channel `number`, a health `version`): guard `DoesExist`+`<> invalid` ONLY, then coerce via `str(Int(x)).trim()` (`Int()` on a String can also RAISE — type-guard the numeric family first). For a possibly-string field that IS safe to compare (e.g. health `status="ok"`), still type-guard `type(s)="String" or "roString"` before the `=`. Same applies at the CALL site: a JSON value passed into a param typed `as String` (e.g. an id in a URL path) must be stringified BEFORE crossing the typed-String interface fn.
- **[gotcha]** `is_admin`/`is_active`/`pin_required_for_admin` arrive from JSON as TINYINT (0/1, sometimes Boolean) — read truthy flags ONLY via `Utilities.IsAdminUser(user)` (is_admin) or the generic `IsTruthyFlag(container,key)` (both type-guard Boolean/Integer/Float, false on invalid/missing). NEVER compare with `<> ""`.
- **[gotcha]** Server JSON field-name landmines bsc can't catch: some list rows have NO top-level `id` — e.g. a live-TV series rule's identifier is `rule_id`. Read the verified server contract in the slice worklog for the exact key before reading any `.id`. The roku/mobile dead hub code uses the WRONG relay path `/api/v1/relay/{id}`; the REAL hub proxy path is `/api/v1/servers/{id}/proxy/{path:.*}` — verify routes against `phlix-hub` source, not against existing client code.
- **[convention]** `GET /api/v1/admin/*` is gated by `AdminMiddleware` (requires `is_admin=1` AND `status='active'`; non-admin→403, no-token→401). `/admin/livetv/*` is registered inside a `try/catch` → the WHOLE route group 404s when Live TV is unconfigured. Per-library mutation routes are BARE `/libraries/{id}/{scan,...}` gated INTERNALLY by `requireAdmin`. `GET /api/v1/auth/me` and `GET /health` (hub + server, public, no auth) are NOT admin-gated. UUID ids path directly (no `UrlEncode`).
- **[convention]** Cross-component callable subs MUST be declared in the target component's `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and bsc does NOT catch it. A scene a PARENT creates+appends+focuses and self-loads on `Init` (or signals back via an OBSERVED FIELD like `loginSucceeded`/`connected`) needs NO interface fn — only entry-points invoked as `scene.Method(...)` across the boundary require it. Each new component `.xml` must ALSO `<script>`-include its full source closure (Storage+Utilities+ApiClient+AppContext+own .brs) — component scope does NOT auto-include `pkg:/source`.
- **[convention]** New scenes use `function OnKeyEvent(key as String, press as Boolean) as Boolean`; back → `Teardown()` + `m.top.Close()` (or eat `back` returning handled=true for screens with no back-out, like Login/Connect). Pair EVERY `ObserveField` with `UnObserveField` in `Teardown` (list itemSelected/itemFocused, every button's buttonSelected, AND the apiTask `response` field). `LibraryScene.brs`'s older `sub OnKeyEvent ... as Boolean` form is the exception — don't copy it.
- **[pattern]** When adding a browse/list or button-action scene that mirrors an existing one, copy the closest template verbatim (ConnectScene ⟵ LoginScene; ProfilesScene ⟵ UserAdminScene). Back the current list with `m.<rows>` (reset to `[]` first) so `itemSelected`/`itemFocused` index maps to the right object; parameterize via the interface fn (fire the load in `LoadFoo`, NOT `Init`, once the id is known). Serialize through ONE ApiTask + `m.pendingOp`, cleared at the TOP of OnApiResponse before any chained refresh; after a mutation `SetStatus(MessageOf(resp))` THEN re-fire the read. When revealing a previously `visible="false"` button after a failed op, also `SetFocus(true)` it — focus does not auto-move to a node that was hidden.
- **[gotcha]** Do NOT both hand-implement/hand-edit a slice in the coordinator AND delegate the SAME slice to subagent(s) — they race / produce no-op duplicate work. This recurs EVERY session (F11b, F11c, F9b, F10, and AGAIN F12a): the coordinator hand-wrote ALL files + hand-appended the worklog implementation-log AND the reviewer section (via `cat >>` heredoc), THEN spawned author + code-reviewer agents for the already-finished work. Decide ONCE up front per slice: delegate impl/review/docs OR do it inline, never both — and never spawn duplicate agents (or two at once) for one job.

- **[convention]** Doc updates for a new scene go in README.md (rewrite the relevant flow prose, add the scene to the Project-Structure component list, fix stale troubleshooting steps) and CLAUDE.md (architecture/flow sections) — NOT DEVELOPER.md (lib/manager-focused). There is NO CHANGELOG.md in the roku repo — do not create one. `phlix-docs` (`docs/clients/roku.md`, `docs/dev/client-roku.md`) is a separate end-user/pre-F0b-build-spec repo and is out of scope unless the slice explicitly names it.
- **[gotcha]** README.md / CLAUDE.md carry STALE pre-F0b Emby-era prose ("Device profile is load-bearing", `/Items/{id}/PlaybackInfo`, `ApiClient.deviceProfile`, hardcoded `localhost:8096` fallback, "server URL comes from the login flow / Settings page"). F0b removed the device profile + Emby routes (canonical `/api/v1` now); F12a moved server-URL entry to the first-run ConnectScene. Fix these in passing when you touch the surrounding section — don't trust existing doc prose as current.
