# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[pattern]** Drive a multi-step API flow (getLibraries→getContinueWatching; getItem→getItemPlaybackInfo→PlayerScene) through ONE observed `ApiTask` node, firing each next op only from the prior op's `OnApiResponse` branch — never two `control="run"` outstanding on one task. Add a re-entrancy guard (e.g. early-return if `m.pendingResume <> invalid`). `ApiTask.request` is a generic `assocarray`, so new op params ride along without any `.xml` change — only add an op branch in `ExecRequest`.
- **[pattern]** Roku resume-from-position: seek on the FIRST `state="playing"` transition guarded by a one-shot `m.resumeApplied` flag (also covers the transcode-fallback PlayHls path). Make `resumeSeconds` an OPTIONAL arg (guard invalid/≤0 → 0) so callers that omit it still play from the start.
- **[gotcha]** Endpoint paths follow TWO conventions — verify which the deployed box serves before changing a client path: continue-watching is `/api/v1/me/continue-watching` (daemon) AND `/api/v1/users/me/continue-watching` (WebPortalRouter); the favorites LIST is `/api/v1/users/me/favorites` (the `/users/me/...` form, NOT `/me/favorites`). Continue-watching items are RAW `playback_state`+`media_items` JOIN rows (NO `poster_url`, 100ns ticks, ≥95%-complete already excluded server-side); favorites items ARE canonical MediaItemShaper-shaped media items.
- **[gotcha]** Search is `GET /api/v1/media?search=<q>` (Bearer) — there is NO `/api/v1/search` route. It matches `name` ONLY (FULLTEXT BOOLEAN MODE OR `name LIKE %q%`, case-insensitive), enforces NO min length server-side, and IGNORES `topLevel` when `search` is set, so a search spans ALL libraries and CAN return `season`/`episode` rows. Same `{items,total,limit,offset}` envelope as browse.
- **[pattern]** Roku on-screen search: add a `Keyboard` node, `ObserveField("text", ...)`, debounce via a NON-repeating `Timer` restarted on each keystroke (`control="stop"` then `"start"`); fire the API op only on the Timer `fire`, and RE-READ `m.keyboard.text` inside the fire handler (the keystroke value is stale). Gate on trimmed length ≥ 2 in BOTH handlers.
- **[gotcha]** `ApiTask` ops set `result.ok = (result.data <> invalid)`, but `ApiClient.request()` returns `raw.json` for ALL status codes and mutation endpoints return a JSON body on BOTH success and failure. So an HTTP-error-with-body (e.g. a 400 on an out-of-range rating) sets `ok=true` and any `not resp.ok` optimistic-revert branch NEVER fires. Mutations through ApiTask cannot detect server rejection; the server is authoritative only on the next read (getItem).
- **[gotcha]** A custom focus state machine over sibling SceneGraph nodes must CONSUME (`handled=true`) every directional key while a zone is entered, AND check intra-zone nav (e.g. header Left/Right between two Buttons) FIRST/gated on the current zone (`m.currentRail = "search"`) so those keys still bubble to grids in OTHER zones. Centralize zone re-entry in a helper (e.g. `FocusHeaderZone()` restoring a remembered `m.headerCol`) and always set `handled=true` at each call site. Framework key bubbling between Buttons/PosterGrids is DEVICE-UNVERIFIABLE — own the input defensively and flag it for device QA.
- **[gotcha]** Do NOT both delegate a fix to a subagent (via SendMessage) AND hand-apply the same edits in the coordinator session — they race on the same file and produce malformed blocks needing a corrective second edit. Pick ONE path: let the fixer do it then verify, OR do it yourself and don't message the fixer.
- **[gotcha]** Don't fully implement a slice yourself in the coordinator (write every file, run the bsc gate, update the worklog) and THEN ALSO spawn a general-purpose implementation subagent for the same slice — in this session the coordinator wrote FavoritesScene.{brs,xml} + the HomeScene edits and passed bsc, then launched an agent to "implement F5b" anyway, which had nothing left to do. Decide up front who implements: delegate the impl OR do it inline, not both.
- **[pattern]** When adding a browse screen that mirrors an existing one (FavoritesScene ⟵ SearchScene), copy the closest template's grid-build + type-routed selection idiom verbatim (`BuildResultCaption`→`EpisodeCaption` for episodes else `name`; `HDPosterUrl = poster_url` else `pkg:/images/placeholder.png`; `OnResultSelected` guards `index`+`invalid` then routes series→SeriesScene.LoadSeries / season→SeasonScene.LoadSeason / else→DetailScene.LoadItem) and the new `.xml` must `<script>`-include the full closure (Storage, Utilities, ApiClient, AppContext, <Scene>.brs).
- **[pattern]** The clean way to combine subagent review with coordinator edits: instruct the review subagent "Do NOT modify any code — review only" and have it APPEND findings to the worklog; the coordinator then applies the fixes itself and re-runs the bsc gate. This sidesteps the same-file race entirely (reviewer writes only to the worklog, coordinator owns the source edits).
- **[pattern]** Mirror the `type()` guard for ARRAYS too: before caching/iterating a server list field (`resp.data.artists`/`.albums`/`.tracks`, `album.tracks`), gate on `type(x) = "roArray"` in addition to `<> invalid` — a `for each` over a non-array JSON value (object/string) crashes at runtime and `bsc` does NOT flag it. Apply this at BOTH the assignment site and any iteration site.
- **[gotcha]** A single shared `m.apiTask` that carries BOTH browse ops AND a play/resume chain needs the in-flight guard applied to EVERY entry point, not just the obvious one. A `m.pendingPlay`/`m.pendingResume` flag that only blocks a second SELECT does NOT block a mode-button/browse op from firing a concurrent `control="run"`. Gate the browse op (`LoadMode`) on `if m.pendingPlay <> invalid then return` too, or set one `m.busy` flag at every `control="run"` and clear it in `OnApiResponse`.
- **[pattern]** Roku resume/play-from-position: seek on the FIRST `state="playing"` transition guarded by a one-shot flag (also covers the transcode-fallback PlayHls path). Make `resumeSeconds` an OPTIONAL arg (guard invalid/≤0 → 0) so music/other callers that omit it play from the start.
- **[gotcha]** Endpoint paths follow TWO conventions — verify which the deployed box serves before changing a client path: continue-watching is `/api/v1/me/continue-watching` (daemon) AND `/api/v1/users/me/continue-watching` (WebPortalRouter); the favorites LIST is `/api/v1/users/me/favorites` (the `/users/me/...` form, NOT `/me/favorites`).

Same `{items,total,limit,offset}` envelope as browse.
- **[gotcha]** Do NOT reuse `getLibraryItems` for a global search — it ALWAYS emits `libraryId=<id>&topLevel=1` (or `parentId` mode). Add a dedicated method that omits libraryId/parentId/topLevel + a matching op branch in `ApiTask.ExecRequest`.
- **[gotcha]** A custom focus state machine over sibling SceneGraph nodes must CONSUME (`handled=true`) every directional key while a zone is entered, AND check intra-zone nav FIRST/gated on the current zone so those keys still bubble to grids in OTHER zones. Framework key bubbling between Buttons/PosterGrids is DEVICE-UNVERIFIABLE — own the input defensively and flag it for device QA.
- **[convention]** Components live in top-level `components/` (git-mv'd out of `source/components/`); `bsconfig.json` globs `manifest + source/**/*.brs + components/**/*.{brs,xml} + images`. Keep new scene files under `components/`, not `source/components/`. (CLAUDE.md still says `source/components/` — it is stale; trust the actual tree.)
- **[convention]** Each NEW component `.xml` must `<script>`-include its FULL source closure — a component scope does NOT auto-include `pkg:/source`. Copy the exact 5-line block from the closest scene (`pkg:/source/lib/Storage.brs`, `Utilities.brs`, `ApiClient.brs`, `AppContext.brs`, then its own `pkg:/components/<Scene>.brs`). A missing include is a runtime "function not found" that `bsc` does NOT catch.
- **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — a `scene.LoadFoo(...)` call from another scene fails at runtime without it and `bsc` does NOT catch it. A scene that a PARENT creates+appends+focuses and self-loads on `Init` (e.g. HomeScene self-creating MusicScene) needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` from another scene require declaration.
- **[fix]** When `bsc` fails BS1140 "Cannot find function '<Helper>'" because a shared helper was defined in a module-specific file the caller doesn't include, MOVE the helper into `source/lib/Utilities.brs` (commonly script-included) rather than adding the niche file to every include list. Delete the original to avoid a duplicate-declaration error.
- **[gotcha]** `roUrlTransfer`'s synchronous `GetToString`/`PostFromString` do NOT expose the HTTP status code. To read `GetResponseCode()` go async: `SetPort` + `AsyncGetToString`/`AsyncPostFromString`, then a bounded `wait(<ms>, port)` for an `roUrlEvent`; set `RetainBodyOnError(true)`. `wait(0, port)` blocks FOREVER and `SetTimeout(ms)` bounds the transfer, NOT the `wait()`.
- **[gotcha]** BrightScript's default numeric type is a 32-bit Integer, so `Int(seconds * 10000000)` for 100ns ticks OVERFLOWS past ~214s. Track position in SECONDS (Float) and convert at the API boundary via a Double-math helper returning `LongInteger`.
- **[pattern]** Bound any SceneGraph repeat-`Timer` poll loop with an explicit counter (reset on start, stop + surface error past a cap). A poll that only stops on ready/failed spins forever if the job hangs.
- **[gotcha]** The media-item `runtime` field is in MINUTES (`ticks/600000000`), NOT seconds — multiply by 60 before `FormatTime`. When a scout/Explore agent reports a field's units, treat it as a hypothesis and prefer a convention already verified against server source.
- **[pattern]** Roku on-screen search: `Keyboard` node + `ObserveField("text", ...)`, debounce via a NON-repeating `Timer` restarted on each keystroke (`stop` then `start`); fire the API op only on the Timer `fire`, and RE-READ `m.keyboard.text` inside the fire handler (the keystroke value is stale). Gate on trimmed length ≥ 2 in BOTH handlers.
- **[pattern]** When adding a browse screen that mirrors an existing one, copy the closest template's grid-build + type-routed selection idiom verbatim, back the CURRENT list with `m.rows` (rebuilt per mode/filter so `itemSelected` index maps to the right object), and pair EVERY `ObserveField` in `Teardown`. `back` calls `Teardown()` + `m.top.Close()` per the SearchScene/SeriesScene/SeasonScene precedent.
- **[pattern]** Verify a music/album scene against the bsc gate with `npx brighterscript@0.72.5 --project bsconfig.json` and grep the log for `error|warn` (EXIT=0 + "clean" = pass). This is the ONLY real static gate — `make lint`/`make test`/CI never fail.
- **[convention]** When staging a feature commit, `git add` the specific source files individually — do NOT `git add .` — so untracked tooling dirs like `.claude/skills/` stay out of the commit.
