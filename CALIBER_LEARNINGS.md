# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[gotcha]** Do NOT both delegate a fix to a subagent (via SendMessage) AND hand-apply the same edits in the coordinator session — they race on the same file, producing malformed blocks that need a corrective second edit. Pick one path: let the fixer do it then verify, OR do it yourself and don't message the fixer.
- **[gotcha]** When a `.brs` value may arrive as either a parsed assoc OR a raw JSON string (e.g. a continue-watching item's `metadata`), guard with `if type(meta) = "roAssociativeArray"` BEFORE calling `.DoesExist`/indexing it. Calling assoc methods on an `roString` crashes at runtime and `bsc` does NOT catch it — an `<> invalid` guard alone is insufficient. Likewise, a server `"key": null` parses to BrightScript `invalid` even though `DoesExist("key")` is true, so guard both `DoesExist` AND `<> invalid` before using an optional value (e.g. `user_data`, `user_data.rating`).
- **[pattern]** Drive a multi-step API flow (getLibraries→getContinueWatching; or getItem→getItemPlaybackInfo→PlayerScene.Show) through ONE observed `ApiTask` node, firing each next op only from the prior op's `OnApiResponse` branch — never two `control="run"` outstanding on one task. Add a re-entrancy guard so a rapid double-select can't fire a second concurrent run. The `ApiTask.request` field is a generic `assocarray`, so new op params (rating/options/itemId) ride along without any `.xml` change — only add an op branch in `ExecRequest`.
- **[gotcha]** The continue-watching endpoint is registered at TWO paths: `/api/v1/me/continue-watching` (daemon, `Application.php` — what the Roku `ApiClient.getContinueWatching()` calls) and `/api/v1/users/me/continue-watching` (`WebPortalRouter`). Note the favorites LIST path is the OTHER convention — `/api/v1/users/me/favorites` (NOT `/me/favorites`). Verify which path the deployed box serves before changing a client path.
- **[gotcha]** Search is `GET /api/v1/media?search=<q>` (Bearer) — there is NO dedicated `/api/v1/search` route. It matches `name` ONLY (FULLTEXT BOOLEAN MODE OR `name LIKE %q%`, case-insensitive), enforces NO min length server-side, and `topLevel` is IGNORED when `search` is set, so a search spans ALL libraries and CAN return `season`/`episode` rows. Same `{items,total,limit,offset}` envelope as browse.
- **[gotcha]** Do NOT reuse `ApiClient.getLibraryItems` for a global search — it ALWAYS emits `libraryId=<id>&topLevel=1` (or `parentId` mode), which scopes/limits results wrongly. Add a dedicated method that omits libraryId/parentId/topLevel and sends only the needed params, plus a matching op branch in `ApiTask.ExecRequest`.
- **[pattern]** Roku on-screen search: add a `Keyboard` node, `ObserveField("text", ...)`, and debounce via a NON-repeating `Timer` restarted on each keystroke (`control="stop"` then `"start"`); fire the API op only on the Timer `fire`, and RE-READ `m.keyboard.text` inside the fire handler (don't capture the keystroke value — it's stale). Gate on trimmed length ≥ 2 in BOTH the keystroke handler and the fire handler.
- **[gotcha]** `ApiTask` ops set `result.ok = (result.data <> invalid)`, but `ApiClient.request()` returns `raw.json` for ALL status codes and the favorite/rating/mutation endpoints return a JSON body (`{message}` / `{error}`) on BOTH success and failure. So an HTTP-error-with-body (e.g. a 400 on an out-of-range rating) sets `ok=true` and any `not resp.ok` optimistic-revert branch NEVER fires — only a true network failure / empty body reverts. Mutations through ApiTask therefore cannot detect server rejection; the server is authoritative only on the next read (getItem). Don't rely on `resp.ok` to catch 4xx unless you change `request()`/`sendRaw` to surface the HTTP status.
- **[gotcha]** A custom focus state machine over sibling SceneGraph nodes (e.g. an `m.actionFocus` driving `SetFocus` across play/favorite/rating Buttons) must CONSUME (`handled=true`) every directional key while the strip is entered — including no-op directions — so the framework's default arrow navigation can't silently move focus to a sibling without updating your state variable, which would then fire the wrong button's `buttonSelected` on OK. (In practice plain `Button` siblings inside a `Rectangle` — not a LayoutGroup/RowList, no `next*` wiring — usually don't auto-navigate, but this is device-only-unverifiable, so own the input defensively.)
- **[gotcha]** Do NOT both delegate a fix to a subagent (via SendMessage) AND hand-apply the same edits in the coordinator session — they race on the same file and produce malformed blocks needing a corrective second edit. This antipattern recurred in a later session (coordinator messaged the fixer the review fix, started a poll, then Edited the file itself anyway). Pick ONE path: let the fixer do it then verify, OR do it yourself and don't message the fixer.
- **[convention]** Components live in top-level `components/` (git-mv'd out of `source/components/`); `bsconfig.json` globs `manifest + source/**/*.brs + components/**/*.{brs,xml} + images` and `make package` ships `manifest source components images`. Keep new scene files under `components/`, not `source/components/`. (CLAUDE.md still says `source/components/` — it is stale; trust the actual tree.)
- **[fix]** When `bsc` fails BS1140 "Cannot find function '<Helper>'" because a shared helper (e.g. `UrlEncode`) was defined inside a module-specific file that the calling component doesn't include, MOVE the helper into `source/lib/Utilities.brs` (commonly script-included) rather than adding the niche file to every component's include list. Delete the original to avoid a duplicate-declaration error.
- **[gotcha]** `roUrlTransfer`'s synchronous `GetToString`/`PostFromString` do NOT expose the HTTP status code, so you cannot detect a 401 (or any status). To read `GetResponseCode()` go async: `SetPort(roMessagePort)` + `AsyncGetToString`/`AsyncPostFromString`, then `wait(...)` for an `roUrlEvent` and call `event.GetResponseCode()`/`event.GetString()`. Set `RetainBodyOnError(true)` so the error-response body stays parseable.
- **[gotcha]** `wait(0, port)` blocks FOREVER until a message arrives — `roUrlTransfer.SetTimeout(ms)` bounds the transfer, NOT the `wait()`. Use a bounded `wait(<ms slightly above SetTimeout>, port)` and treat a zero/non-`roUrlEvent` return as a timeout (then `AsyncCancel()`).
- **[gotcha]** BrightScript's default numeric type is a 32-bit Integer, so `Int(seconds * 10000000)` for 100ns playback ticks OVERFLOWS past ~214 seconds (silently wrong on long media). Track position/throttle in SECONDS (Float) internally and convert to ticks only at the API boundary via a Double-math helper returning `LongInteger` (e.g. `SecondsToTicks(seconds as Double) as LongInteger` → `seconds * 10000000.0`). Put shared converters in `source/lib/Utilities.brs`.
- **[pattern]** Bound any SceneGraph repeat-`Timer` poll loop with an explicit counter (`m.pollCount`, reset when the timer starts, stop the timer + surface an error past a cap like >30 polls). A poll that only stops on ready/failed spins forever if the job hangs — terminal states are not guaranteed to arrive.
- **[gotcha]** Cross-component callable subs MUST be declared in the component `<interface>` as `<function name="LoadFoo"/>` — without it a `scene.LoadFoo(...)` call from another scene fails at runtime and `bsc` does NOT catch it (it only validates intra-scope symbols). A scene that a PARENT creates+appends+focuses and which self-loads on `Init` (e.g. FavoritesScene fired via `OnFavoritesPressed`) needs NO `<interface><function>`; only entry-points invoked as `scene.Method(...)` from another scene require declaration.
- **[gotcha]** The media-item `runtime` field is in MINUTES (server derives it as `ticks/600000000` in MediaItemShaper.php), NOT seconds — multiply by 60 before `FormatTime`. When a scout/Explore agent reports a field's units or contract detail, treat it as a hypothesis and prefer the convention already verified against server source by a prior slice over a fresh scout's claim.
- **[gotcha]** `getLibraryItems` has two modes: `options.parentId` → direct-children mode (`parentId=<id>`, OMITS `topLevel`) for series→season→episode drill-down; otherwise `libraryId=<id>&topLevel=1` (top-level browse). `/media` returns children `ORDER BY name` only, so re-sort season/episode lists client-side (`SortByEpisodeOrder` in Utilities). Do NOT reuse `getLibraryItems` for global search — it ALWAYS emits libraryId/topLevel (or parentId); add a dedicated `search(query, options)` method + ApiTask op branch instead.
- **[gotcha]** When a `.brs` value may arrive as either a parsed assoc OR a raw JSON string (e.g. a continue-watching item's `metadata`), guard with `if type(meta) = "roAssociativeArray"` BEFORE `.DoesExist`/indexing — calling assoc methods on an `roString` crashes at runtime and `bsc` does NOT catch it. Likewise a server `"key": null` parses to `invalid` even though `DoesExist("key")` is true, so guard BOTH `DoesExist` AND `<> invalid` before using an optional value (e.g. `user_data.rating`).
- **[pattern]** Drive a multi-step API flow (getLibraries→getContinueWatching; getItem→getItemPlaybackInfo→PlayerScene) through ONE observed `ApiTask` node, firing each next op only from the prior op's `OnApiResponse` branch — never two `control="run"` outstanding on one task. - **[pattern]** Roku resume-from-position: seek on the FIRST `state="playing"` transition guarded by a one-shot `m.resumeApplied` flag (also covers the transcode-fallback PlayHls path). Make `resumeSeconds` an OPTIONAL arg (guard invalid/≤0 → 0) so callers that omit it still play from the start.
- **[gotcha]** Endpoint paths follow TWO conventions — verify which the deployed box serves before changing a client path: continue-watching is `/api/v1/me/continue-watching` (daemon) AND `/api/v1/users/me/continue-watching` (WebPortalRouter); the favorites LIST is `/api/v1/users/me/favorites` (the `/users/me/...` form, NOT `/me/favorites`). Continue-watching items are RAW `playback_state`+`media_items` JOIN rows (NO `poster_url`, 100ns ticks, ≥95%-complete already excluded server-side); favorites items ARE canonical MediaItemShaper-shaped media items.

- **[gotcha]** Don't fully implement a slice yourself in the coordinator (write every file, run the bsc gate, update the worklog) and THEN ALSO spawn a general-purpose implementation subagent for the same slice — in this session the coordinator wrote FavoritesScene.{brs,xml} + the HomeScene edits and passed bsc, then launched an agent to "implement F5b" anyway, which had nothing left to do. Decide up front who implements: delegate the impl OR do it inline, not both.
- **[pattern]** When adding a browse screen that mirrors an existing one (FavoritesScene ⟵ SearchScene), copy the closest template's grid-build + type-routed selection idiom verbatim (`BuildResultCaption`→`EpisodeCaption` for episodes else `name`; `HDPosterUrl = poster_url` else `pkg:/images/placeholder.png`; `OnResultSelected` guards `index`+`invalid` then routes series→SeriesScene.LoadSeries / season→SeasonScene.LoadSeason / else→DetailScene.LoadItem) and the new `.xml` must `<script>`-include the full closure (Storage, Utilities, ApiClient, AppContext, <Scene>.brs).
