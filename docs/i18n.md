# Internationalization (i18n) — R7.12

## Overview

The phlix-roku-client uses a lightweight JSON-based i18n system. All user-facing strings live in `locale/<locale>/strings.json` and are referenced by symbolic keys from BrightScript via `Translate(key)`. The mechanism is **live**: `PhlixApp.Init` calls `InitLocale()` (`source/lib/AppContext.brs`), which loads the catalog at startup; `Translate()` also retries lazily until a load succeeds.

- Single base locale (`en_US`) plus six shipped sibling catalogs (`de_DE`, `es_ES`, `fr_FR`, `it_IT`, `ja_JP`, `pt_BR`)
- Device-locale selection with `en_US` fallback
- A dedicated **error registry** (`errors` section) driven by one deterministic mapping law — see [Error catalog](#error-catalog-the-mapping-law-and-two-families)
- Five static checks in `scripts/verify-runtime.sh`:
  - **Check 19** — greps the three i18n-scoped files for hardcoded user-facing strings that bypass the catalog
  - **Check 20** — proves every `Translate("…")` key actually **resolves** against the catalog (the silent raw-key-rendering gap Check 19 cannot see)
  - **Check 21** — pins every sibling catalog to `en_US`: identical flattened key sets, `{placeholder}` parity, newline-escape parity, string-only leaves
  - **Check 22** — proves the wire census: every server-verified syncplay error code resolves through the mapping law to an `en_US` `errors_*` entry, and the law/Task wire-in keep their shape
  - **Check 23** — keeps the client-minted `local.*` error family **separate** from the wire census: shape law, catalog resolution, wire-census honesty (exactly 16 server codes), section purity, and call-site membership

## Directory Structure

```
phlix-roku-client/
└── locale/
    ├── en_US/
    │   └── strings.json    ← base locale + sole fallback (source of truth)
    ├── de_DE/strings.json
    ├── es_ES/strings.json
    ├── fr_FR/strings.json
    ├── it_IT/strings.json
    ├── ja_JP/strings.json
    └── pt_BR/strings.json
```

> ⚠️ The `locale/` tree is part of the channel package: the Makefile `package`
> target zips it (`… source components images locale`) and `bsconfig.json`
> lists `locale/**/*`. If it is ever dropped from packaging, every `Translate()`
> call silently falls back to rendering raw keys on device.

## Locale File Format

`locale/en_US/strings.json` is organized into sections matching the source files that own the strings. Sections nest **bare** keys:

```json
{
  "_metadata": {
    "locale": "en_US",
    "language_name": "English (US)",
    "version": "1.0.0",
    "source_files": [
      "components/SettingsScene.brs",
      "components/DetailScene.brs",
      "source/lib/Utilities.brs"
    ]
  },
  "settings": { "button_cancel": "Cancel", ... },
  "detail":   { ... },
  "utilities": { ... },
  "common":   { ... }
}
```

### Sections

| Section | Source File(s) | Description |
|---------|----------------|-------------|
| `settings` | `components/SettingsScene.brs` | UI labels, dialog titles/messages, button labels, status text |
| `detail` | `components/DetailScene.brs` | Favorite/rating/watch button labels, error dialog strings |
| `utilities` | `source/lib/Utilities.brs` | Display labels from pure utility functions (`PhotoAlbumCaption`, `RatingLabel`) |
| `common` | — | Standard strings shared across files (`OK`, `Error`, `Retry`) |
| `errors` | law-driven: `SyncPlayTask.brs` / `SyncPlayScene.brs` via `Utilities.brs` | **Error registry.** One entry per server-verified wire error code, the `fallback` line, and each client-minted `local_*` code. Every key must belong to one of those three accounted families (Check 23 keeps this bidirectional) |
| `syncplay` | `components/SyncPlayScene.brs` | Watch-party room UI: list/form status lines, roles, member-count and visibility caption fragments |

### Key Convention (flattened, section-prefixed)

The catalog nests bare keys under their section; **call sites always pass the flattened `<section>_<bareKey>` form**:

```json
"settings": { "button_cancel": "Cancel" }
```

```brightscript
label.text = Translate("settings_button_cancel")   ' ✅ the convention
```

`LoadLocaleStrings()` flattens the parsed catalog once at load time via
`FlattenLocaleCatalog()` in `source/lib/Utilities.brs`, so the prefixed call
style resolves with zero indirection. `Translate()` resolution order (first hit
wins):

1. exact match in the flattened table — the convention every call site uses
2. nested probe `raw[section][key]` — legacy support for bare-key callers
3. return the key unchanged — graceful fallback; a raw key rendered on screen
   is visible breakage rather than a silently wrong string

Only **string** leaves participate: `FlattenLocaleCatalog()` skips a
non-string value while building the flat table, and `Translate()`'s nested
probe applies its own string guard, so a future array/object leaf renders the
visible raw key instead of type-crashing `Translate()`'s `as String` return on
device. Check 20 rejects such leaves in CI, so the skips are defense-in-depth,
not a supported authoring style.

Key names use `snake_case` and encode semantic context (`{section}_{concept}_{modifier}`):

- `settings_section_account` — section header
- `settings_item_user_email` — a menu list item
- `settings_desc_user_email` — the item's description text
- `settings_status_logged_in_as` — a runtime status label (uses `{email}` placeholder)
- `detail_favorite_add` — button label
- `utilities_rating_pg13` — display label from `RatingLabel()`
- `syncplay_members_count` — caption fragment with a `{count}` token substituted by name at the call site
- `errors_local_connect_failed` — error registry entry produced by the mapping law from the client-minted code `local.connect_failed`

Placeholders in status/error strings use `{name}` syntax:

```json
"status_logged_in_as": "Logged in as: {email}"
```

## Error catalog: the mapping law and two families

The `errors` section is not hand-keyed at call sites — it is a **registry** derived by one deterministic mapping law (`SyncPlayErrorCodeToKey` in `source/lib/Utilities.brs`):

```
key = "errors_" + LCase(trim(code))  with "." and "-" replaced by "_"
invalid / non-string / empty code    ->  errors_fallback
```

Two families feed that one law, and **provenance is carried by the census, not the key shape**:

| Family | Census (source of truth) | Provenance | Example code → key |
|--------|--------------------------|------------|--------------------|
| **Wire** | `SyncPlayKnownErrorCodes()` — exactly the 16 codes verified against the server's SyncPlay sendError literals (12 legacy SCREAMING + 4 dotted `syncplay.*` twins) | arrives on a `syncplay_error` frame | `syncplay.group_full` → `errors_syncplay_group_full` |
| **Client-minted** | `SyncPlayLocalErrorCodes()` — `local.<snake_name>` codes the device invents for its own failures | produced on-device; **never** ride a frame | `local.connect_failed` → `errors_local_connect_failed` |

Doctrine:

- **Error-code-first.** A recognized code resolves the localized catalog line; the server's English `message` is only the debug fallback for codes this build does not recognize (`LocalizeSyncPlayError`, wire side).
- **The wire census stays honest.** Client strings must never be pushed into `SyncPlayKnownErrorCodes()` — that list is the estate's claim about what the *server* emits, and Check 22 pins it at 16. Mint a `local.*` code instead; Check 23 rejects a wire census containing one.
- **`local.*` is a reserved prefix.** The server registry's code shapes are SCREAMING legacy and dotted namespaced (`syncplay.…`); `local.…` is minted by this client alone.
- **No blank task errors.** `LocalizeSyncPlayLocalError` never returns `""` (catalog hit → `errors_fallback` → visible raw-key echo), because the task thread has no other channel to report through — the wire-side resolver may return `""` precisely because its caller holds a last-resort literal.

### Adding a client-minted error code

1. Add `local.<name>` to `SyncPlayLocalErrorCodes()` in `Utilities.brs`.
2. Add the **bare** key `local_<name>` (law output minus the section prefix) with its English line to `locale/en_US/strings.json` → `errors`, and the translated line to all six siblings (Check 21 parity).
3. Call `LocalizeSyncPlayLocalError("local.<name>")` at the display site (`SyncPlayTask.brs` does this inside `EmitError`; scenes call it directly with a literal code).
4. `make verify-runtime` — Check 23 proves resolution, family separation, section purity, and the call-site membership of every literal; the portable harness proves Check 23 can go red.

## Loading, Mount, and Locale Selection

All of this lives in `source/lib/Utilities.brs` (`LoadLocaleStrings` / `Translate`).

**Mount — direct `pkg:/` read.** The catalog is read with
`ReadAsciiFile("pkg:/locale/<tag>/strings.json")`. The earlier scaffold used
`locale://locale/en_US/strings.json`, but the `locale://` protocol is only
mounted when the manifest declares `locale=`/`country_code=` keys — which this
channel's manifest does not — so `roFileSystem.Exists()` was always false and
the catalog silently never loaded. `pkg:/` needs no manifest wiring and is the
established pattern in this repo (every other asset URL is `pkg:/` or relative).

**Device-locale selection.** `CreateObject("roAppInfo").GetCurrentLocale()`
returns the device locale; firmware varies between `"en-US"` and `"en_US"`, so
the tag is normalized (`-` → `_`) before resolving the `locale/<tag>/` folder.

**Fallback chain (first hit wins):**

1. `pkg:/locale/<normalized-device-tag>/strings.json` — only if it exists **and** has content
2. `pkg:/locale/en_US/strings.json` — the base locale; the sole fallback and the sole Translate-literal source of truth for CI (Checks 20/21)
3. no catalog → `Translate()` returns raw keys (lazily retried until a load succeeds)

`ReadAsciiFile` returns `""` for both missing and empty files, so an
empty/whitespace-only device catalog is explicitly treated as **missing** (we
check the trimmed content, never just file existence).

## Static Checks

`scripts/verify-runtime.sh` runs all three checks as part of `make verify-runtime`.

### Check 19 — hardcoded strings (R7.12)

**What it checks:** The three scoped files — `SettingsScene.brs`, `DetailScene.brs`, and `Utilities.brs` — for user-facing string literals that appear to be hardcoded (not pulled from the locale file).

**What it flags:** Assignments to known UI fields:
- `dialog.title`, `dialog.message`, `dialog.buttons`
- `.text = "<string>"` on `Label`, `statusLabel`, `detailLabel`, `loadingLabel`
- `.title = "<string>"` on `Button` nodes
- Strings passed to `ShowErrorDialog()`

**What it allows (allow-list):**
- URL literals (`http://`, `https://`, `ws://`, etc.) and hostnames (`localhost`, `192.168.x.x`, etc.)
- Numeric string literals (`"0"`, `"1"`)
- `Chr()` calls for structural characters (line feed `Chr(10)`, etc.)
- Function names, field names, variable names
- BrightScript built-in calls (`str()`, `Int()`, `FormatTime()`, etc.)
- String operations (`.Trim()`, `.Lower()`, `.Replace()`, etc.)
- `true`/`false` booleans
- Comment-only lines

### Check 20 — key resolution (i18n key-resolution fix)

Check 19 cannot see the inverse defect: a `Translate("key")` call whose key has
no catalog entry renders the raw key silently. Check 20 closes that gap:

- Extracts every literal `Translate("…")` key across `source/` + `components/`
  (multi-line-safe regex; comment runs masked out before scanning — both
  whole-line `' comments and trailing inline `code ' Translate("x")` comments,
  with a double-quote-aware scanner so `"Don't"` never starts a comment)
- Rejects non-string catalog leaves (`Translate()` returns `as String`; a
  non-string value is a latent device crash), mirroring the runtime skip
- Builds the flattened key set from `locale/en_US/strings.json` using the same
  `<section>_<bareKey>` convention the runtime loader uses
- Also binds to the `RatingLabel()` function and asserts every string in its
  literal `labels` array — the one dynamic call site
  (`Translate(labels[n])`) that literal scanners cannot see — resolves
- Deterministic, read-only; exits non-zero with a per-key miss listing otherwise

The check is falsifiable by construction: a `Translate("bogus_key")` anywhere
in the scanned tree (e.g. dropped into an untracked scratch file
`source/zz.brs`) makes `bash scripts/verify-runtime.sh` exit 1 with a
`CHECK20: Translate key 'bogus_key' has no flattened entry …` line. Removing the
scratch returns it to green. The synthetic CI-layout run in
`tests/scripts/verify-runtime-portable.sh` exercises the same path and asserts
the Check 20 header appears in a passing run.

### Check 21 — locale parity (multi-locale catalogs)

Checks 19/20 guard the code path and the `en_US` base. Once sibling catalogs
ship, a new silent defect class appears: `Translate()` on a German device
renders whatever `locale/de_DE/strings.json` holds, so a catalog that drifted
from the base renders raw keys / broken formats **only on that locale**. Check
21 pins every `locale/<tag>/strings.json` to the base:

- **(a) Key-set identity** — the flattened (`<section>_<bareKey>`) key set of
  every sibling must exactly match `en_US`; missing AND extra keys both fail,
  listed per file
- **(b) Placeholder parity** — the `{token}` multiset per shared key must be
  identical (`{email}` survives translation or the check goes red)
- **(c) Newline-escape parity** — `\n` counts per shared key (the `\n\n` dialog
  bodies), plus **non-string leaves rejected in all catalogs** (same
  `as String` defense Check 20 applies to `en_US`)
- **(d) Fallback pinned** — the literal `"pkg:/locale/en_US/strings.json"` must
  remain in `Utilities.brs`; `en_US` stays the sole fallback and Check 20's sole
  comparison catalog (it is intentionally untouched — per-check gates stay
  independent, proven by the portable harness's red-21 leg: Check 21 goes red
  while Checks 14/20 stay green)
- `_metadata.locale` must equal its folder name and `_metadata.source_files`
  must match `en_US` (catches copy-paste drift)

Self-proof (scratch copy, same trick as the portable harness): delete
`common.ok` from a sibling → `CHECK21: … 1 key(s) missing … common_ok`; add a
bogus key → `… not present in locale/en_US …`; strip `{email}` from
`settings_status_logged_in_as` → `placeholder mismatch`. Each restores to green.

### Check 22 — wire-code census resolution (W5 thin-client)

`syncplay_error` frames localize through the mapping law. Silent key-echo
fallback must not hide a missing translation, so Check 22 re-derives the law in
CI and requires:

- every literal in `SyncPlayKnownErrorCodes()` flattens to an existing `en_US`
  `errors_<key>` entry, with no two codes colliding on one key
- `errors_fallback` exists (the generic localized last-resolve line)
- the normalizer keeps its shape (`LCase` + `.`/`-` → `_`) and `Translate()`'s
  nested-probe sections list still includes `errors`
- `SyncPlayTask.brs` still routes `syncplay_error` text through
  `LocalizeSyncPlayError()` (the wire-in)

Cross-locale parity of the errors section is Check 21's job — it compares **all**
sections of every locale folder against `en_US`.

### Check 23 — client `local.*` family separation (this adoption lane)

The syncplay task/scene surfaces also produce **client-generated** failures that
never appear on the wire (socket setup, REST create/join/leave failures). They
share the mapping law under a reserved `local.` mint prefix, so the wire census
could quietly absorb them and lie about what the server emits. Check 23 keeps
the two censuses honest:

- **(a)** `SyncPlayLocalErrorCodes()` exists and every entry matches
  `local.<snake_name>`
- **(b)** each local code normalizes to an existing `en_US` `errors_local_*`
  entry, collision-free within the family
- **(c)** the wire census still lists **exactly 16** server-verified codes, none
  starting with `local.`, and no wire code normalizes onto a local key
- **(d)** section purity: every `errors` key belongs to wire ∪ {`fallback`} ∪
  local — the registry is checked **bidirectionally**, so an unaccounted string
  cannot squat in it
- **(e)** every `EmitError("…")` argument in `SyncPlayTask.brs` and every
  `LocalizeSyncPlayLocalError("…")` literal across `source/` + `components/`
  names a census member — a task error may never regress to a raw display
  literal (call-site scanning uses Check 20's comment masker, so doc-style
  examples like `LocalizeSyncPlayLocalError("local.*")` in a header comment
  never register)

Falsifiable in CI-layout via `tests/scripts/verify-runtime-portable.sh`: the
red-23 leg rewrites one `EmitError("local.connect_failed")` call site to a raw
`EmitError("Connect failed")` in a scratch copy and asserts CHECK23 fires while
CHECK21/CHECK22 stay green (gate independence).

## Shipping a locale

1. **Folder name = normalized device tag.** The loader maps
   `roAppInfo.GetCurrentLocale()` through `.Trim().Replace("-","_")`, so the
   folder must be the underscore form of the BCP-47 tag Roku firmware reports:
   `locale/es_ES/`, `locale/ja_JP/`, `locale/pt_BR/`. A `locale/es-ES/` folder
   would never be selected. Use `language_country` (Roku reports region-qualified
   tags; bare `locale/es/` never matches).
2. **Copy the base and translate values only.**
   `cp -a locale/en_US locale/<tag>`, then edit string values plus
   `_metadata.locale` / `_metadata.language_name`. Never add, remove, or rename
   keys — Check 21 (a) rejects both directions.
3. **Keep every `{placeholder}` verbatim** in whatever word order the language
   needs (the token is substituted by name at the call site, position-free).
   Keep `\n` escapes where `en_US` has them.
4. **Translation judgment bar:** brand names (`Phlix`) and MPA certificate
   codes (`G`, `PG`, `PG-13`, `R`, `NC-17`, `X`) stay verbatim; `OK` and the
   `ISO ` prefix (note the trailing space — it is part of the string) stay as-is;
   everything else should read naturally to a native speaker, not
   translation-shaped English.
5. **Run the gates:** `make verify-runtime` (Checks 20+21) and
   `bash tests/scripts/verify-runtime-portable.sh` (locale-resolution leg walks
   your folder through the loader's real normalization contract).
6. **Fallback chain unchanged:** an unshipped device locale still lands on
   `en_US`, so adding a folder is purely additive — no code change, no
   manifest key (`pkg:/` mount), nothing to unregister to remove it.

## How to Add a New String

1. **Add the bare key + value** under the appropriate section in `locale/en_US/strings.json`
2. **Mirror it into every sibling catalog** — `locale/de_DE/`, `locale/es_ES/`,
   `locale/fr_FR/`, `locale/it_IT/`, `locale/ja_JP/`, `locale/pt_BR/` — or
   Check 21 goes red listing the missing key per file
3. **Reference it** with `Translate("<section>_<bareKey>")` (e.g. `Translate("settings_button_save")`)
4. **Run `make verify-runtime`** — Check 19 stays clean, Check 20 proves the new key resolves in the base, Check 21 proves every locale mirrors it

## Adding a New Locale

See **Shipping a locale** above for the full procedure. In short: create
`locale/<language>_<country>/strings.json` as a translated copy of the base,
set `_metadata.locale` to the folder name, and `make verify-runtime` (Check 21)
enforces key-set, placeholder, and escape parity from the first commit. A new
folder is picked up automatically once it matches the normalized device locale
— no code change required.

## Historical Notes

- R7.12 scaffolded the catalog plus Check 19. The loader existed but was doubly broken: the `locale://` mount was never declared in the manifest, and the call-site key style (flattened) did not match the catalog layout (nested bare keys), so every `Translate()` silently returned the raw key. Both were fixed in the key-resolution change; the earlier "R7.13: mechanism not yet wired" placeholder note in this document is obsolete.
- The six sibling catalogs (`de_DE`, `es_ES`, `fr_FR`, `it_IT`, `ja_JP`, `pt_BR`) shipped with Check 21; `en_US` remains the sole fallback and source of truth.
- W5 (thin-client error localisation) added the `errors` registry, the mapping law, `LocalizeSyncPlayError`, and Check 22 — `syncplay_error` frames now resolve error-code-first instead of rendering server English.
- The 2026-09 syncplay adoption lane localized the remaining client-generated surfaces: the `SyncPlayScene.brs` REST/status path moved into the new `syncplay` section plus `local.*` minted error codes, and `SyncPlayTask.brs` `EmitError` switched from raw English literals to census codes. Check 23 guards the wire-vs-client family separation. (`SyncPlayScene.xml` chrome labels — "Watch Together", "Create Room", … — remain inline XML attributes; extracting them needs a render-time contract and is future work.)
