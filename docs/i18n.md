# Internationalization (i18n) — R7.12

## Overview

The phlix-roku-client uses a lightweight JSON-based i18n scaffold. All user-facing strings are centralized in `locale/<locale>/strings.json` and referenced by symbolic keys fromBrightScript code. This enables:

- Single base locale (`en_US`) with a clean structure for adding new locales
- A static check (Check 19 in `scripts/verify-runtime.sh`) that greps for hardcoded strings in the three i18n-scoped files
- Clear visibility into which strings have been internationalized vs. which still need extraction

## Directory Structure

```
phlix-roku-client/
└── locale/
    └── en_US/
        └── strings.json    ← base locale (en_US)
```

## Locale File Format

`locale/en_US/strings.json` is organized into sections matching the source files that own the strings:

```json
{
  "_metadata": {
    "locale": "en_US",
    "language_name": "English (US)",
    "version": "1.0.0",
    "source_files": [
      "components/SettingsScene.brs",
      "components/DetailScene.brs",
      "source/lib/Utilities.brs"
    ]
  },
  "settings": { ... },
  "detail":   { ... },
  "utilities": { ... },
  "common":   { ... }
}
```

### Sections

| Section | Source File(s) | Description |
|---------|----------------|-------------|
| `settings` | `components/SettingsScene.brs` | UI labels, dialog titles/messages, button labels, status text |
| `detail` | `components/DetailScene.brs` | Favorite/rating/watch button labels, error dialog strings |
| `utilities` | `source/lib/Utilities.brs` | Display labels from pure utility functions (`PhotoAlbumCaption`, `RatingLabel`) |
| `common` | — | Standard strings shared across files (`OK`, `Error`, `Retry`) |

### String Key Naming Convention

Keys use `snake_case` and encode the semantic context:

```
{section}_{concept}_{modifier}
```

Examples:
- `settings_section_account` — section header
- `settings_item_user_email` — a menu list item
- `settings_desc_user_email` — the item's description text
- `settings_status_logged_in_as` — a runtime status label (uses `{email}` placeholder)
- `detail_favorite_add` — button label
- `detail_error_favorite_save` — error dialog message
- `utilities_photo_album_undated` — display label for undated items

Placeholders in status/error strings use `{name}` syntax, matching theBrightScript ` substitute` pattern:

```json
"settings_status_logged_in_as": "Logged in as: {email}"
```

## Static Check (Check 19)

`scripts/verify-runtime.sh` runs Check 19 as part of `make verify-runtime`.

**What it checks:** The three scoped files — `SettingsScene.brs`, `DetailScene.brs`, and `Utilities.brs` — for user-facing string literals that appear to be hardcoded (not pulled from the locale file).

**What it flags:** Assignments to known UI fields:
- `dialog.title`, `dialog.message`, `dialog.buttons`
- `.text = "<string>"` on `Label`, `statusLabel`, `detailLabel`, `loadingLabel`
- `.title = "<string>"` on `Button` nodes
- Strings passed to `ShowErrorDialog()`

**What it allows (allow-list):**
- URL literals (`http://`, `https://`, `ws://`, etc.) and hostnames (`localhost`, `192.168.x.x`, etc.)
- Numeric string literals (`"0"`, `"1"`)
- `Chr()` calls for structural characters (line feed `Chr(10)`, etc.)
- Function names, field names, variable names
- BrightScript built-in calls (`str()`, `Int()`, `FormatTime()`, etc.)
- String operations (`.Trim()`, `.Lower()`, `.Replace()`, etc.)
- `true`/`false` booleans
- Comment-only lines

## How to Add a New String

1. **Add the key + value** to the appropriate section in `locale/en_US/strings.json`
2. **Reference it** in the BrightScript file using a lookup helper (not yet implemented — see "Future Work" below)
3. **Run `make verify-runtime`** to confirm Check 19 stays clean
4. When adding a new locale (e.g., `locale/de_DE/strings.json`), translate the values without changing the keys

## Extracted Strings

The following strings were extracted from the three scoped files into `locale/en_US/strings.json` at R7.12 scaffolding time:

### SettingsScene.brs (40 strings)
Section headers, menu item labels, item descriptions, dialog titles/messages, button labels, and runtime status strings for all six settings sections (Account, Server, Playback, Captions, Watch History, Notifications, About).

### DetailScene.brs (12 strings)
Favorite/rating/watch button labels and `ShowErrorDialog` error messages for failed favorite, rating, and watched-state operations.

### Utilities.brs (9 strings)
`PhotoAlbumCaption()` fallback `"Undated"` label and the seven `RatingLabel()` content-rating strings (`G`, `PG`, `PG-13`, `R`, `NC-17`, `X`, `UNRATED`).

## Future Work

The locale lookup mechanism (a `tr(key as String) as String` function or equivalent) is not yet wired into the BrightScript files. The scaffold exists; connecting it is tracked as R7.13.

Planned steps:
1. Implement a `tr(key as String) as String` function in `source/lib/Utilities.brs` that reads from the active locale JSON
2. Add locale switching support (detect system locale, persist user preference in `Storage`)
3. Wire all three scoped files to use `tr()` calls instead of hardcoded strings
4. Add `locale/de_DE/`, `locale/fr_FR/`, etc. with translated values

## Adding a New Locale

```bash
mkdir -p locale/de_DE
cp locale/en_US/strings.json locale/de_DE/strings.json
# Edit locale/de_DE/strings.json with translated values, update _metadata.locale
```

Maintain identical key names across all locales. Only the `_metadata` block and string values change.
